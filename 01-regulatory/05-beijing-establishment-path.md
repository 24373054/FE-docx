# 北京电子数据司法鉴定机构筹建路径

## 1. 文件目的

把北京市公开的司法鉴定机构登记、电子数据实验室和仪器配置要求转化为分阶段筹建门禁。

核心原则是先确认范围和路径，再进行不可逆投入。

## 2. 当前项目状态

截至2026年7月30日：

- 未确定最终申请法人；
- 未确定获主管机关确认的申请项目；
- 未确定正式场所；
- 未采购司法鉴定生产设备；
- 未完成具名鉴定人配置；
- 未取得北京市司法行政机关的书面路径答复；
- 未启动行政许可申请。

因此本文件仅能形成需求和预算假设，不能形成开业或获批时间承诺。

## 3. 已核验的北京公开要求

北京市司法局公开的配置指南对电子数据实验室列明了功能区域和设备方向。

基础功能区域包括：

- 案件受理及预检室；
- 样品保管区域；
- 防静电的电子数据分析区域；
- 档案资料区域。

按业务需要还可能包括：

- 洁净操作空间；
- 电磁屏蔽空间；
- 远程服务器或云数据处理条件；
- 专门的数据销毁和安全存储设施。

实际面积、隔离方式和设备组合须与拟申请项目及现场评审要求对应。

## 4. 筹建顺序

### 阶段A：书面确认

1. 确定拟申请主体；
2. 定义拟解决的专门性问题；
3. 映射0301至0304候选项目；
4. 形成场所、人员和设备问题包；
5. 向北京市司法局/属地部门获得可归档答复；
6. 形成是否进入下一阶段的管理决定。

### 阶段B：可逆设计

- 场地选址比较；
- 平面布局和数据流设计；
- 用户需求说明；
- 设备类别和功能参数；
- 安全、消防和网络隔离设计；
- 人员招聘与资格核验；
- 预算、时间和退出方案。

### 阶段C：受控实施

只有在范围和路径确认后，才可以：

- 签署带退出条件的场地合同；
- 按批准URS采购；
- 建设功能区；
- 安装、验收和验证设备；
- 正式运行质量体系；
- 组织内部模拟评审。

## 6. 场所设计原则

场所至少区分：

- 委托方活动区；
- 受理、清点和拍照区；
- 原始物项保管区；
- 工作副本制作区；
- 技术分析区；
- 复核和报告区；
- 档案区；
- 服务器、密钥和备份区。

物项、人员和数据流尽量单向，避免未授权交叉。

样品保管与普通办公存储不得混用。

## 7. 设备需求方法

每项设备从任务反推：

`拟申请项目 → 方法 → 关键功能 → 性能指标 → 验收样本 → 维护/校准 → 退出`

典型类别可能包括：

- 取证工作站；
- 存储介质复制和写保护设备；
- 移动终端数据提取设备；
- 数据恢复与密码分析工具；
- 日志、数据库、网络数据分析工具；
- 元数据和文件分析工具；
- 存储、备份、销毁和审计设施；
- 公共链数据获取、复算和多源校核工具。

目录中出现的类别不等于本项目必须全部采购。

## 8. 采购门禁

采购申请必须包含：

- 对应的拟申请项目；
- 对应方法和控制ID；
- 当前官方要求来源；
- 用户需求说明及限制；
- 候选产品比较；
- 数据外传和许可风险；
- 验收、验证和回归方案；
- 校准、维护和停产风险；
- 总拥有成本；
- 范围未获批时的退出方案。

未取得阶段批准不得下单。

## 9. 专家评审准备

模拟评审应能回答：

- 为什么需要该区域或设备；
- 与哪一申请项目、方法相连；
- 人员是否获得授权；
- 正常、边界和失败样本是否验证；
- 原始数据和工作副本如何隔离；
- 工具更新后如何重新验证；
- 设备故障和停电时如何保护物项；
- 报告如何回到完整技术记录。

只展示软件界面不构成能力证明。

## 10. 主要停止条件

出现下列情形即停止不可逆投入：

- 主管机关否定拟申请范围；
- 申请主体或地址未确定；
- 具名人员无法满足配置；
- 场所用途或消防存在重大障碍；
- 核心工具要求数据无控制地出境；
- 供应商不提供验证所需信息；
- 预算不包含运行、维护和能力保持；
- 把辅助可视化当作核心鉴定结论。

## 11. 验收清单

- [ ] 申请项目和审批路径已获得可归档确认；
- [ ] 平面图覆盖受理、保管、分析和档案区域；
- [ ] 样品、人员和数据流已经评审；
- [ ] UPS、消防、防磁、防静电和监控需求完整；
- [ ] 每项设备与项目、方法和人员对应；
- [ ] 设备所有权或合法使用权证据明确；
- [ ] 验收、验证、维护和停用规则已设计；
- [ ] 远程/云取证和可视化保持可选且受控；
- [ ] 专家现场演示能够形成证据闭环；
- [ ] 未在书面确认前发生不可逆采购。
