# 数据安全、个人信息与跨境处理控制

## 1. 文件目的

为区块链电子数据研究、技术服务和未来司法鉴定建立数据安全与个人信息门禁。

本程序适用于收集、存储、使用、加工、传输、提供、公开和删除全生命周期。

## 2. 适用法律基线

当前基线包括：

- 《中华人民共和国个人信息保护法》；
- 《中华人民共和国数据安全法》；
- 2026年1月1日起施行修改后的《网络安全法》；
- 《网络数据安全管理条例》；
- 《个人信息保护合规审计管理办法》；
- 《促进和规范数据跨境流动规定》；
- 2026年生效的个人信息出境认证管理规则。

每次真实数据处理前必须查新。

## 3. 区块链数据并非当然匿名

公钥地址、交易图谱或设备标识在单独状态下可能无法识别自然人。

但在与以下数据组合后，可能构成个人信息或敏感个人信息：

- 交易平台实名信息；
- 手机号、邮箱、证件号；
- IP、设备和登录记录；
- 钱包备份、通信和合同；
- 地址标签和聚类结论；
- 涉案、财务、行踪或身份材料。

项目不得以“链上公开”为由免除个人信息和数据安全审查。

## 4. 角色

- **个人信息处理者/数据处理者**：由具体法人和业务关系确定；
- **业务负责人**：说明目的、范围和必要性；
- **安全负责人**：分类分级、访问、事件和第三方控制；
- **合规负责人**：合法基础、告知同意例外、跨境和审计判断；
- **方法负责人**：落实最小数据和可复核要求；
- **处理人员**：仅按授权和方法处理；
- **独立复核人**：核对数据边界和对外披露。

责任角色不能只写在模板中，必须具名。

## 6. 处理前门禁

每个数据集进入项目之前必须回答：

1. 谁是处理主体；
2. 数据由谁、以何权限提供；
3. 处理目的是什么；
4. 包含哪些个人信息、敏感信息或重要数据候选；
5. 是否确有必要；
6. 是否可以使用合成、去标识或更小范围；
7. 谁可访问；
8. 在哪里处理和保存；
9. 是否会被供应商、模型或境外人员访问；
10. 保存多久、如何冻结和销毁；
11. 发生事件时通知谁；
12. 哪些输出可以交付。

任一关键问题无法回答时不得导入。

## 7. 合法基础与告知

合法基础必须由具体业务和法律关系确定。

不得默认：

- 委托合同天然覆盖全部个人信息处理；
- 公开链数据可无限抓取和画像；
- 刑事/司法例外自动适用于普通企业；
- 客户声明可以替代本公司的独立审查；
- 一次同意覆盖新目的、新接收方和跨境；
- 技术可行等于法律允许。

同意不是唯一可能的基础，也不是万能免责。

## 8. 研发数据策略

默认优先顺序：

1. 完全合成数据；
2. 公开且不含可识别信息的数据；
3. 经验证的匿名化数据；
4. 最小化且受控的去标识数据；
5. 仅在必要、批准和隔离下使用真实材料。

研发环境不得连接生产密钥、真实委托材料或个人云盘。

## 9. 跨境判断

跨境不只包括主动上传，还可能包括：

- 境外SaaS、RPC、模型或工单系统；
- 境外员工或供应商远程访问；
- 日志、遥测、崩溃报告和备份；
- 跨境协作仓库；
- 境外母公司集中管理；
- 向境外客户交付可识别数据。

合规负责人应按当时有效门槛判断安全评估、标准合同、认证或豁免路径。

未完成判断前默认禁止出境。

## 10. 第三方与工具

引入工具前至少评估：

- 数据是否离开受控环境；
- 厂商是否留存或训练；
- 子处理者及所在区域；
- 加密、身份认证和日志能力；
- 删除、导出和审计能力；
- 安全事件响应；
- 许可终止后的数据返还；
- 是否支持离线部署和证据复现。

免费API和公共RPC也属于外部数据接收方候选。

## 11. 留存与销毁

留存表至少区分：

- 原始证据；
- 工作副本；
- 派生分析；
- 报告和披露副本；
- 访问与安全日志；
- 研发样本；
- 备份；
- 依法冻结或争议保全的数据。

销毁不得破坏有效证据保全、诉讼保全或法定档案义务。

## 12. 监管结论分级与决策矩阵

|命题|等级|当前决定|升级条件|
|---|---|---|---|
|公开链地址永远不是个人信息|D|按可识别性和组合风险逐项判断|具体数据集评估|
|真实案件材料可直接用于模型训练|D|默认禁止|新的合法基础、最小化和专项批准|
|境外RPC查询不涉及数据出境|C|作为跨境候选评估|证明请求不含受保护数据|
|默认境内离线处理是当前稳健策略|C|作为架构约束|正式业务评估批准例外|
|个人信息合规审计要求可能适用|A/C|建立触发器，不虚构法定频率|主体规模与法定情形确定|

## 13. 验收清单

- [ ] 数据目录、分类分级和负责人完整；
- [ ] 每项处理的合法基础、目的和必要性有记录；
- [ ] 地址、标签和身份材料的组合风险已评估；
- [ ] 敏感信息和案件秘密有加强保护；
- [ ] 研发使用合成或最小化数据；
- [ ] 访问授权、加密、密钥和日志已验证；
- [ ] 第三方和所有跨境路径已识别；
- [ ] 留存、冻结、销毁和主体请求流程已设计；
- [ ] 安全事件分级、控制和通知责任明确；
- [ ] 未完成审查的数据不能进入环境。
