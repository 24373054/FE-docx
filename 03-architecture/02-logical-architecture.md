# 逻辑架构与服务职责

## 1. 文件目的

把任务、身份、证据对象、采集、链适配、解析、标准化、资产账本、路径/规则/标签、假设、复核、报告、审计、离线验证、配置和通知拆分为职责清晰的候选逻辑组件。

“服务”表示逻辑职责，不表示已存在微服务、产品代码或部署实例。

## 2. 当前状态与原则

- 当前没有产品系统、数据库、消息总线或服务端程序；
- 现有证据包和脚本只验证部分数据模型/完整性；
- 逻辑组件可由受控人工流程或未来软件实现，但记录不变量相同；
- 原始对象不可覆盖，事实/推断/人工决定分层；
- 路径、规则、标签和假设不能自动发布结论。

## 3. 逻辑层

|层|职责|主要对象|
|---|---|---|
|治理接入|任务、授权、身份、配置|Case、Authorization|
|采集证据|来源、会话、原始对象|AcquisitionSession、RawObject|
|协议事实|适配、解析、标准化|NormalizedFact、AssetDelta|
|分析推断|路径、规则、标签、假设|RuleExecution、Hypothesis|
|复核报告|HumanDecision、Review、Report|ReviewRecord、ReportCitation|
|保障|审计、通知、离线验证|CustodyEvent、日志、包|

## 4. 服务间不变量

- 每个调用携带任务、授权、主体、关联ID和对象身份；
- 所有输出不可变并保留输入、版本、参数、环境和人员/服务身份；
- 错误、超时、重复和部分结果显式状态化；
- 业务服务不得直接更改授权、真值或审计记录；
- 自动化候选必须经授权人员复核。

## 5. 详细控制要求

### ARC-002-C001｜案件服务

- 管理任务类型、范围、状态、参与者、数据域、期限和变更。
- 当前不使用法定“案件”状态对外，真实受理为0。

### ARC-002-C002｜身份权限服务

- 将自然人/服务身份、组织关系、角色、任务、授权、到期和冲突绑定。
- 系统角色不得超越ORG-004书面授权。

### ARC-002-C003｜证据对象服务

- 创建/查询不可变对象、父关系、哈希、密级、状态和保管事件。
- 禁止覆盖原始对象或静默更换引用。

### ARC-002-C004｜采集编排器

- 按批准计划调用来源/节点，保存实际请求、响应、重试、错误和会话。
- 编排器不决定数据可信或结论。

### ARC-002-C005｜Bitcoin适配器

- 限定网络、客户端、原始区块/交易、确认规则和字节解析版本。
- 当前只覆盖已验证对象类型，身份/路径推断排除。

### ARC-002-C006｜EVM适配器

- 区分链ID、区块/交易/回执/日志、最终性、合约代码和历史状态。
- 未完成原始对象与真值验证前保持候选。

### ARC-002-C007｜TRON适配器

- 区分网络、区块/交易、receipt/log、资源/手续费和最终性语义。
- 不直接继承EVM字段和假设。

### ARC-002-C008｜协议解析器

- 解析器输入原始字节/受控响应，输出带字段来源与解析版本的事实。
- 未知/不支持字段不得默认0或空值掩盖。

### ARC-002-C009｜标准化服务

- 标准化保留链原生字段、精度、单位、时间和来源，另生成跨链视图。
- 不能为统一Schema牺牲语义或把缺失转为确定值。

### ARC-002-C010｜资产账本服务

- 用不可变AssetDelta记录资产、方向、金额、精度、规则和守恒检查。
- 非标准代币、内部交易、燃料费和销毁/铸造须显式处理。

### ARC-002-C011｜路径引擎

- 输出候选路径、算法、约束、排除、分支和未覆盖范围。
- 不把图路径自动解释为自然人控制、违法资金或唯一流向。

### ARC-002-C012｜规则引擎

- 每次运行绑定规则ID/版本、输入、参数、命中、未命中和错误。
- 规则命中属于规则层，不等于事实或法律结论。

### ARC-002-C013｜标签服务

- 保存标签值、对象、来源、证据、时间、许可、置信、冲突和版本。
- 不透明供应商标签不能覆盖内部事实或自动进入报告。

### ARC-002-C014｜假设服务

- 假设记录命题、依据、反证、替代解释、状态和决定。
- 假设不能修改原始事实；未验证保持candidate/disputed。

### ARC-002-C015｜复核服务

- 向独立复核人提供冻结输入、预期、原始对象和重算路径。
- 复核意见、差异、保留和批准不可被执行人覆盖。

### ARC-002-C016｜报告服务

- 仅引用已批准对象和结论层级，生成可追溯报告/附件/更正关系。
- 模板渲染不能绕过质量和发布批准。

### ARC-002-C017｜审计服务

- 以追加事件记录身份、访问、配置、对象、规则、决定、发布和异常。
- 审计服务独立于业务管理员，支持导出与完整性验证。

### ARC-002-C018｜离线验证器

- 从冻结包验证Schema、哈希、父关系、P0计算和报告引用。
- 不能依赖生产数据库/互联网或被测服务的隐藏状态。

### ARC-002-C019｜配置服务

- 管理方法、工具、数据源、环境、阈值和功能开关的版本/批准/作用域。
- 运行时默认值必须可见，未批准配置拒绝加载。

### ARC-002-C020｜通知服务

- 通知只传播状态/行动，不携带超出必要的证据或秘密。
- 送达、失败、重试和接收人授权有记录；通知不改变业务状态。

## 6. 典型流

受理创建Case/Authorization → 采集编排形成RawObject → 适配/解析/标准化形成事实 → 分析服务形成规则/路径/标签/假设 → 独立复核形成HumanDecision → 报告服务引用批准对象 → 审计/离线验证贯穿全程。

## 7. 错误与幂等

所有写入使用幂等键/对象身份；部分成功不得标记整体完成；重试生成attempt记录；错误区分输入、授权、来源、解析、验证、冲突和系统故障。

## 8. 主要风险与控制

|风险|控制|停止|
|---|---|---|
|逻辑服务等于已开发|当前状态声明|无部署证据|
|适配器语义混同|链原生字段|映射不明|
|候选自动成结论|复核/层级|批准缺失|
|默认值掩盖缺失|显式unknown|字段不明|
|业务改审计|追加/独立|完整性失败|
|离线验证依赖生产|冻结包|无法独立|

## 9. 记录

服务目录、职责、数据契约、错误、幂等、版本、威胁、测试和架构决定按QMS-002保存。

## 10. 验收准则

- [ ] 20个逻辑职责无责任重叠/空洞；
- [ ] ARC-004/005对象和事件贯穿；
- [ ] 链原生语义与标准化分开；
- [ ] 自动候选、人工决定和报告批准分离；
- [ ] 错误、幂等、审计和离线验证可执行；
- [ ] 未把逻辑组件写成已开发系统。

## 11. 当前结论

逻辑组件已形成候选职责模型，实际实现数量为0。未来实现可合并部署，但不得合并关键独立性和数据不变量。

## 12. 架构决策与接口约束

- [ ] 服务职责与主体/角色授权一致；
- [ ] 每个输入输出映射ARC-004对象；
- [ ] 所有变换产生ARC-005事件；
- [ ] 错误、幂等和版本契约冻结；
- [ ] 离线验证不依赖被测实现。

接口最小上下文：actor/service、case_id、authorization_id、correlation_id、input object/hash、schema/method/tool/config version、classification、timestamp、result/error。
