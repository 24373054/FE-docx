# 证据对象与数据模型

## 1. 文件目的

本文件定义案件、授权、采集、原始对象、派生对象、事实、推断、复核、报告、保管和交付之间的可追溯数据模型。模型用于阻止三类混淆：

- 把文件、记录或界面显示等同于已经核验的事实；
- 把规则/统计推断等同于协议层事实；
- 把对象哈希一致等同于来源真实、获取合法或方法有效。

模型是逻辑规范，不代表数据库、系统或生产控制已实现。当前仅可在公开数据和经批准模拟数据中验证。

## 2. 适用范围与边界

### 2.1 纳入对象

- 委托/研究任务及其授权边界；
- 采集会话、数据源、工具和运行环境；
- 原始、标准化和派生对象；
- 协议字段、资产变化、规则执行和人工判断；
- 复核、报告引用、保管、交付和留存动作。

### 2.2 排除

- 以本模型自动认定自然人、企业或实际控制人；
- 以地址、聚类或标签自动认定违法属性、主观故意或资金性质；
- 在模型中保存私钥、助记词、账户口令或访问令牌；
- 由技术字段替代法律授权、司法判断或资质结论；
- 将不完整或冲突输入强制填成确定值。

## 3. 核心设计原则

1. **不可变对象**：原始对象和已发布版本不原位修改。
2. **追加事件**：状态变化和保管动作追加记录，不覆盖历史。
3. **显式血缘**：派生对象必须引用全部直接父对象。
4. **事实分层**：原始观察、标准化事实、规则推断、统计推断和人工决定分开。
5. **三值状态**：允许`known`、`unknown`、`not_applicable`，禁止用0或空串掩盖未知。
6. **拒绝优先**：授权、来源、完整性或方法前提失败时停止并保留原因。
7. **稳定标识**：ID不嵌入姓名、证件号、钱包秘密或可变业务含义。
8. **版本锁定**：Schema、方法、工具、规则和数据源均有独立版本。
9. **可复算引用**：报告引用定位到对象、字段或计算记录。
10. **最小化**：只保存实现明确目的所需的数据和关系。

## 4. 标识、时间和数值原语

### 4.1 标识规则

|标识|格式建议|约束|
|---|---|---|
|`case_id`|`CASE-<随机或序列>`|去标识、不复用|
|`object_id`|`OBJ-<类型>-<稳定后缀>`|包内唯一；跨包引用另加包ID|
|`event_id`|`EVT-<时间有序随机值>`|唯一、不可由时间单独推导|
|`source_id`|`SRC-<类型>-<后缀>`|同一逻辑来源版本变化需新记录|
|`person_id`|内部受控人员ID|公开包用角色化标识|
|`method_id`|受控方法号+版本|不得只写方法名称|
|`tool_id`|受控工具号+版本/构建|在线服务同时记录服务快照信息|

ID只能用于引用，不能作为身份真实性或对象完整性证明。

### 4.2 时间

- 事件时间使用RFC 3339并包含时区；
- 同时记录`observed_at`、`recorded_at`和适用时的`source_time`；
- 区块时间、节点接收时间、HTTP时间和操作系统时间不得合并为单一“交易时间”；
- 时间精度与来源一起保存；
- 时钟同步来源、偏差或未知状态写入`EnvironmentRecord`；
- 无可靠时区或精度时记录`unknown`及原因。

### 4.3 数值

- 链上整数值以最小单位的十进制字符串保存，禁止二进制浮点；
- 同时保存`asset_id`、`unit`、`decimals`和协议上下文；
- 显示金额是派生字段，不覆盖原始整数；
- 法币估值必须独立记录价格源、时点、市场、币种、方法和限制；
- 缺失、溢出、截断、舍入和无法解析必须显式状态化。

## 5. 详细控制要求

|控制ID|对象|最低要求|拒绝或未知条件|
|---|---|---|---|
|ARC-004-C001|Case|目的、范围、分类、状态、负责人、授权集合和版本关系|目的或授权边界缺失|
|ARC-004-C002|Authorization|授权人/来源、对象、动作、期限、地域、限制、证据位置和状态|口头或范围歧义|
|ARC-004-C003|AcquisitionSession|会话ID、开始/结束、人员、环境、数据源、请求、响应、异常和封存结果|时间、来源或工具无法确定|
|ARC-004-C004|EvidenceItem|逻辑证据项、描述、来源、关联会话、敏感级别和对象集合|只有结论无承载对象|
|ARC-004-C005|RawObject|字节级原始对象、路径、大小、哈希、媒体类型、获取方式和只读状态|对象被改写或无哈希|
|ARC-004-C006|DerivedObject|全部父对象、转换、方法、工具、参数、输出哈希和失败记录|父对象不全或不可重放|
|ARC-004-C007|NormalizedFact|字段名、值、类型、单位、来源定位、映射规则、置信状态|默认值替代缺失或无来源定位|
|ARC-004-C008|AssetDelta|资产、最小单位整数、方向、主体角色、交易/事件引用和守恒检查|资产身份或小数位未知|
|ARC-004-C009|RuleExecution|规则ID/版本、输入集合、参数、输出、命中理由、反例和执行状态|规则版本或输入快照缺失|
|ARC-004-C010|Hypothesis|命题、依据、反向证据、替代解释、置信级别和限制|把假设写为协议事实|
|ARC-004-C011|HumanDecision|决定人、权限、输入、理由、时间、状态和覆盖/偏离说明|匿名决定或无理由覆盖机器结果|
|ARC-004-C012|SourceRecord|来源类型、标识、控制方、网络位置、版本、访问条件和可靠性限制|单一来源却宣称交叉核验|
|ARC-004-C013|ToolRecord|工具名、版本/构建、二进制或发布物哈希、验证状态和允许用途|无法固定版本或验证状态未知|
|ARC-004-C014|EnvironmentRecord|操作系统、时区、时钟、硬件/容器、网络、节点及关键配置|环境影响结果但未记录|
|ARC-004-C015|ReviewRecord|复核人、独立性、范围、样本、重算、差异、决定和证据|P0差异未关闭|
|ARC-004-C016|ReportCitation|报告版本、段落/表格、对象ID、字段/偏移、计算ID和引用类型|关键事实无法回溯|
|ARC-004-C017|CustodyEvent|事件类型、对象、操作者、时间、位置、前后状态、原因和前事件引用|事件序列断裂或主体不明|
|ARC-004-C018|DeliveryPackage|包类型、清单、根哈希算法/值、披露批准、渠道、状态和回执|无批准或接收校验失败|
|ARC-004-C019|RetentionAction|对象范围、动作、依据、到期/保全、批准、执行和证明|法律保全有效时销毁|
|ARC-004-C020|HashAndSignature|对象、字节范围、算法、值、计算工具、时间；签名另含密钥/证书标识和验签|算法不明、范围歧义或验签未通过|

当前20项控制均未达到`implemented`。模型通过文档评审后，仍需Schema、样例、负向测试和两次端到端演练。

## 6. 对象关系

### 6.1 主关系

```text
Case
 ├─ Authorization*
 ├─ AcquisitionSession*
 │   ├─ SourceRecord*
 │   ├─ ToolRecord*
 │   ├─ EnvironmentRecord*
 │   └─ RawObject*
 ├─ EvidenceItem*
 │   └─ RawObject / DerivedObject / NormalizedFact
 ├─ RuleExecution* -> Hypothesis* -> HumanDecision*
 ├─ ReviewRecord*
 ├─ ReportCitation*
 ├─ CustodyEvent*
 ├─ DeliveryPackage*
 └─ RetentionAction*
```

星号表示零至多，不表示对象可以无条件缺失。是否必需由包类型、阶段和方法决定。

### 6.2 派生有向无环图

派生关系必须形成有向无环图（DAG）：

- `RawObject`不能有数据父对象，但必须有来源和采集会话；
- `DerivedObject`至少一个父对象；
- `NormalizedFact`必须引用原始/派生对象中的字段、JSON Pointer、字节偏移或查询结果行；
- `RuleExecution`引用冻结输入集合，不直接修改输入；
- `Hypothesis`引用事实或规则输出，同时可引用反向证据；
- `HumanDecision`可以接受、拒绝或限制假设，但不改变底层事实；
- 检测到环、孤儿父ID或跨包未声明引用时，包验证失败。

### 6.3 事实层级

|层级|示例|允许表达|不得表达|
|---|---|---|---|
|L0原始观察|RPC响应字节、区块原始字节|“对象中字段为X”|“X必然真实”|
|L1标准化事实|交易ID、输入输出、日志主题|“按规则V1解析为X”|“地址由某自然人控制”|
|L2确定性计算|最小单位求和、路径枚举|“在冻结输入和规则下结果为X”|超出输入边界的完整性|
|L3规则推断|共同输入启发式命中|“规则R命中并存在限制”|“确定同一控制人”|
|L4统计推断|模型评分、相似度|“模型M输出0.8”|“80%法律责任”|
|L5人工决定|采纳、排除、限制结论|“复核人基于证据决定X”|把决定反写为原始字段|

## 7. 状态与版本

### 7.1 通用对象状态

|状态|含义|
|---|---|
|`draft`|字段未冻结|
|`recorded`|已登记但未做完整性验证|
|`verified`|规定的机器/人工完整性检查通过|
|`reviewed`|独立复核完成|
|`approved`|具名批准在限定范围内使用|
|`blocked`|存在阻断缺口|
|`superseded`|由新版本替代，历史保留|
|`withdrawn`|不再允许使用，原因保留|
|`destroyed`|按批准销毁，仅保留证明|

不同对象可限制允许状态。例如`RawObject`不使用`approved`表示内容真实；`Authorization`的`approved`只表示授权记录有效，不表示具体采集符合授权。

### 7.2 不可变与更正

- 已进入`verified`及以上状态的内容更改必须生成新对象/版本；
- 更正对象使用`supersedes_id`关联前版本；
- 撤回不删除历史对象；
- 外部来源变更生成新`SourceRecord`快照；
- 方法、工具或规则升级不自动重算历史结果，先做影响分析；
- 兼容迁移保留旧值、迁移规则、执行记录和前后哈希。

## 8. 缺失、冲突和不确定性

### 8.1 值状态

每个可能缺失的关键字段至少有：

- `value_status`: `known`、`unknown`、`not_applicable`、`redacted`或`conflicted`；
- `reason_code`;
- `reason_detail`;
- `source_refs`;
- `resolved_by`和`resolved_at`（如已解决）。

`unknown`不是失败的同义词；如果方法允许对其他字段继续处理，应保留局部结果并限制结论。如果未知字段是P0前提，则整体方法拒绝。

### 8.2 多源冲突

多源值不一致时：

1. 各来源观察分别保存；
2. 不以最后写入值覆盖；
3. 记录网络、节点、版本、高度/最终性、时间和查询参数；
4. 执行预先规定的冲突解析；
5. 无法解析则标`conflicted`；
6. 报告展示冲突对结论的影响。

## 9. 安全与隐私约束

- 秘密材料不进入业务模型，只保存密钥管理系统中的不敏感引用；
- 自然人/企业身份数据与公开链数据逻辑分区，并记录关联授权；
- 公开包使用角色ID和模拟案件ID；
- 标签来源、许可、获取日期、作用域和置信边界必须登记；
- 删除请求、法律保全和留存冲突由`RetentionAction`记录；
- 查询、导出和复制属于保管/访问事件，不能只依赖应用日志；
- 测试数据不得通过复制真实案件后简单改名生成。

## 10. Schema验证要求

Schema至少验证：

- 必填字段、类型、枚举和格式；
- ID唯一性和引用存在性；
- 路径安全和包内约束；
- SHA-256格式、非负字节数；
- 派生对象至少一个父对象；
- 原始对象不允许数据父对象；
- 不允许DAG环；
- 枚举外状态拒绝而非静默接受；
- 未知值必须有原因；
- 金额采用字符串整数；
- 时间包含时区；
- 破坏性版本变化被拒绝或显式迁移。

JSON Schema本身不能验证字节哈希、权限真实性、DAG全部语义或人员独立性，必须配合只读验证器和人工复核。

## 11. 错误分类

|错误码族|示例|处理|
|---|---|---|
|`AUTH-*`|授权缺失、过期、越界|停止采集/分析|
|`SRC-*`|来源不可识别、版本漂移|保留记录并拒绝关键结论|
|`OBJ-*`|对象缺失、哈希/大小不符|隔离包|
|`LIN-*`|父引用缺失、环、转换不明|阻断派生结果|
|`VAL-*`|类型、枚举、单位、时间错误|修复需新版本|
|`CON-*`|多源或字段冲突|按规则解析或无法判断|
|`REV-*`|独立性不足、P0差异|不得批准|
|`DEL-*`|披露越界、传输校验失败|停止交付|
|`RET-*`|保全冲突、销毁无批准|停止动作并升级|

错误记录包含对象、规则、发现时间、发现人、实际值、预期、影响范围、临时控制和关闭证据。

## 12. 架构决策与接口约束

### ADR-004-01：原始对象按字节不可变

- **决定**：任何解析、格式转换、解压、去标识或显示均生成派生对象。
- **理由**：文本“内容看起来相同”不能证明字节相同。
- **代价**：增加存储和对象数量。
- **验收**：修改原始对象后哈希测试必须失败。

### ADR-004-02：推断与事实分层

- **决定**：规则、模型和人工判断分别建模。
- **理由**：地址归属、资金性质等不能由链上字段直接推出。
- **代价**：报告组装和查询更复杂。
- **验收**：报告引用必须声明引用层级。

### ADR-004-03：金额使用最小单位整数字符串

- **决定**：核心模型不使用浮点金额。
- **理由**：避免精度和跨语言序列化差异。
- **代价**：显示层需显式换算。
- **验收**：超大整数及不同小数位资产有固定测试向量。

### ADR-004-04：状态变化追加而非覆盖

- **决定**：关键状态和保管动作以事件追加。
- **理由**：保留谁在何时基于什么做了改变。
- **代价**：需要投影当前状态和校验事件序列。
- **验收**：撤回后历史批准事件仍可检索。

### ADR-004-05：当前manifest Schema是受限子集

- **决定**：现有[`evidence-manifest.schema.json`](../schemas/evidence-manifest.schema.json)继续服务公开验证样例，但不得称为完整模型实现。
- **理由**：直接破坏现有样例会丢失可复算基线。
- **后续**：通过版本化Schema补充包类型、授权、根哈希算法、状态和遗漏字段。
- **验收**：兼容测试明确旧包通过范围与新包拒绝条件。

### 接口约束

- 序列化默认UTF-8、无BOM；规范化签名另行定义，不直接对任意格式化JSON签名；
- 枚举采用小写ASCII稳定值，显示中文由呈现层完成；
- 所有跨对象引用使用ID，不以文件名或数组位置关联；
- API/RPC响应原字节与解析对象分开保存；
- 导入未知字段在主版本不兼容时拒绝，不静默丢弃；
- 导出时必须声明Schema版本、数据分类和对象计数；
- 分页、排序和过滤参数是采集/派生记录的一部分；
- 报告锚点必须在文档版本变化后重新验证。

## 13. 验收与演练

- [ ] 20个对象控制均有具体Schema或人工检查；
- [ ] 正常样例能够从Case追踪到报告引用和交付回执；
- [ ] 缺授权、孤儿父对象、DAG环和哈希冲突被阻断；
- [ ] 未知、冲突、遮盖和不适用不会被编码为0；
- [ ] 第二人员可从RawObject重建一个P0 NormalizedFact；
- [ ] 规则推断无法伪装成协议事实；
- [ ] 超大金额、时区差异和来源漂移有测试；
- [ ] 两次端到端模拟后再申请升级文档状态；
- [ ] 数据架构、方法、质量、合规和运行角色具名评审；
- [ ] 批准前所有测试仍保持真实生命周期状态。
