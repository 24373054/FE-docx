# 安全架构与取证就绪设计

## 1. 文件目的

定义资产、威胁、身份、权限、密钥、加密、制品/依赖、恶意文件、网络、日志、漏洞、测试、事件和取证就绪要求。

本文件不表示安全平台已部署或通过等级保护、渗透测试、合规审计等外部评价。

## 2. 当前状态与原则

- 当前无生产资产、身份平台、密钥服务、SIEM、沙箱或漏洞平台；
- 公开仓库不存真实案件、个人信息和秘密；
- 安全以零默认信任、最小权限、职责分离、不可覆盖记录和可恢复为原则；
- 资产私钥/助记词托管明确排除；
- 安全控制不能被“链上公开”或“研究阶段”绕过。

## 3. 安全域

身份与管理、接入隔离、任务处理、证据/审计、节点、备份恢复、离线验证各自拥有独立控制面与数据流。

## 4. 威胁模型

威胁主体包括外部攻击者、恶意文件/供应链、错误供应商、越权内部人员、共享账号、失误、数据主体/客户误传、节点欺骗和灾难。模型区分保密性、完整性、可用性、公正性与可追溯性。

## 5. 详细控制要求

### ARC-007-C001｜资产清单

- 资产登记所有硬件、软件、服务、数据、身份、密钥、节点、供应商和文档基线。
- 无所有者、密级、状态或位置的资产不得处理受控数据。

### ARC-007-C002｜威胁建模

- 对每个关键流识别主体、入口、信任边界、滥用、控制、残余风险和验证。
- 主体/数据/架构重大变化触发更新。

### ARC-007-C003｜身份认证

- 每个自然人/服务使用唯一身份，验证生命周期、组织关系和状态。
- 禁止共享账号；系统身份不自动产生业务授权。

### ARC-007-C004｜多因素认证

- 管理、高信任区、远程、敏感数据和密钥操作强制MFA。
- 恢复/备用因子同等受控并审计。

### ARC-007-C005｜最小权限

- 权限按主体、任务、活动、数据域、环境、期限和最小操作授予。
- 定期复核并在到期/离职/冲突/事件时撤销。

### ARC-007-C006｜职责分离

- 身份/权限、密钥、证据写入、审计、发布和删除必要分离。
- 小团队无法分离时引入外部复核或保持blocked。

### ARC-007-C007｜密钥管理

- 密钥生成、存储、使用、轮换、备份、恢复、撤销和销毁有双控/日志。
- 不接收客户虚拟资产密钥。

### ARC-007-C008｜静态加密

- 敏感对象、备份、设备和秘密按风险加密，密钥与数据分离。
- 加密不替代访问、保留和安全删除。

### ARC-007-C009｜传输加密

- 跨主机/区域/外部传输使用验证身份和现代加密，记录证书/端点。
- 禁止为调试长期跳过TLS验证。

### ARC-007-C010｜代码签名

- 实际脚本/制品使用哈希或经验证签名绑定来源、版本和批准。
- 签名不等于安全或方法正确。

### ARC-007-C011｜依赖供应链

- 依赖/镜像/工具记录来源、版本、哈希、SBOM、许可、漏洞和构建。
- 未知/高危依赖不得进入高环境。

### ARC-007-C012｜恶意文件隔离

- 所有外部文件先进入隔离区，类型/解压/恶意内容/宏/脚本检查。
- 失败或未知文件不得直接进入任务/证据区。

### ARC-007-C013｜沙箱执行

- 必须执行不可信对象时使用无生产秘密、最小网络、可重置、全日志沙箱。
- 沙箱结果视为分析线索，不能替代原始对象保全。

### ARC-007-C014｜网络分段

- 外部、接入、节点、任务、证据、管理、日志、备份和离线区分段。
- 跨段默认拒绝、最小白名单和双向审计。

### ARC-007-C015｜审计日志

- 记录身份、认证、访问、对象、配置、权限、密钥、工具、发布和安全事件。
- 业务/系统管理员不能删除本人日志。

### ARC-007-C016｜异常检测

- 检测越权、批量导出、失败登录、日志中断、制品变化、数据异常和节点偏离。
- 告警阈值、抑制和误报有版本与复核。

### ARC-007-C017｜漏洞管理

- 资产/依赖漏洞按来源、严重性、可利用、暴露、数据和补丁分级。
- 高危未缓解时阻断相应发布/运行。

### ARC-007-C018｜渗透测试

- 只有范围、授权、环境、数据保护、停止门和修复责任明确后执行。
- 未授权扫描/攻击外部节点或第三方禁止；当前没有已执行测试。

### ARC-007-C019｜事件响应

- 与SOP-008闭合分级、保全、隔离、通知、恢复和CAPA。
- 安全关闭不自动关闭结果完整性/质量影响。

### ARC-007-C020｜取证就绪

- 日志、时间、对象、身份、配置、网络和保管链应支持事件重建且最小过度采集。
- 取证就绪不授权监控员工/客户全部活动。

## 6. 安全控制层

预防：身份/MFA、权限、加密、分段、供应链。

检测：日志、完整性、异常、漏洞。

响应：隔离、撤权、恢复、CAPA。

证据：统一时间、不可变对象、保管链和导出。

## 7. 数据生命周期

接收前分类 → 隔离扫描 → 受控导入 → 最小访问/处理 → 不可变记录 → 加密交付 → 保留/法律暂停 → 经批准销毁。

## 8. 主要风险与控制

|风险|控制|停止|
|---|---|---|
|共享/过权账号|唯一身份/MFA|无法归责|
|秘密泄露|密钥服务/扫描|凭据暴露|
|恶意检材|隔离/沙箱|检测未知|
|供应链污染|锁定/SBOM|制品不明|
|日志被删|独立审计|完整性失败|
|未授权安全测试|范围授权|第三方受影响|
|过度监控|目的/最小化|无依据采集|

## 9. 记录

资产、威胁、身份、权限、密钥、加密、依赖、扫描、网络、日志、漏洞、测试、事件和例外按公司机密保存。

## 10. 验收准则

- [ ] 资产与威胁覆盖关键流；
- [ ] 身份/MFA/权限/职责分离可执行；
- [ ] 密钥、加密、依赖和恶意文件受控；
- [ ] 网络/日志/异常/漏洞与事件闭合；
- [ ] 取证就绪兼顾最小化；
- [ ] 当前未虚构部署或外部测试。

## 11. 当前结论

安全目标架构已定义，控制实施数量仍为0；只有通过实际配置、演练和独立测试才能升级。

- [ ] 日志/异常/事件/恢复演练；
- [ ] 依赖、漏洞和制品门与发布闭合；
