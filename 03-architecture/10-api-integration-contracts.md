# API与外部集成契约

## 1. 文件目的

规定未来内部服务、节点/RPC、客户/合作方和供应商接口的版本、契约、认证授权、签名、幂等、分页、限流、重试、错误、原始响应、精度、时区、地址、文件、回调、兼容与测试。

当前没有生产API或客户集成；本文件只定义设计和验收要求。

## 2. 适用范围与原则

- 内部服务API、批处理/文件契约、节点/RPC代理和外部回调；
- 接口不直接传递秘密、私钥或未授权真实数据；
- 原始来源响应与标准化响应分开保存；
- 缺失、未知、错误和部分结果显式表达；
- 所有写入可幂等、可审计、可关联对象/授权。

## 3. 契约层

传输（TLS/文件介质）→ 身份授权 → 请求上下文 → 业务Schema → 错误/重试 → 审计/原始对象 → 版本兼容。任何层失败均不能默认成功。

## 4. 最小上下文

request_id、correlation_id、idempotency_key（写入）、actor/service、case_id/alias、authorization_id、purpose、classification、schema/api version、requested_at、source/network和签名/完整性信息。

## 5. 详细控制要求

### ARC-010-C001｜API版本

- 版本应区分破坏性语义变化和兼容扩展，并可映射实现/Schema。
- 未指定版本请求不得静默使用latest。

### ARC-010-C002｜OpenAPI契约

- HTTP API使用受控OpenAPI或等效机器契约，包含Schema、错误、安全和示例。
- 文档生成不替代实现契约测试；非HTTP接口使用等效规范。

### ARC-010-C003｜认证授权

- 先认证唯一身份，再按主体、任务、活动、数据域、目的和期限授权。
- API密钥/令牌存在不等于业务授权。

### ARC-010-C004｜请求签名

- 高风险外部/回调可绑定方法、路径、关键头、body hash、时间、nonce和密钥ID。
- 签名失败/过期/重放拒绝；签名不证明业务内容真实。

### ARC-010-C005｜幂等键

- 创建/变更接口要求作用域内唯一幂等键，重复返回同结果/状态。
- 负载不同却复用键视为冲突，不覆盖原请求。

### ARC-010-C006｜分页

- 定义稳定排序、游标、页面大小、快照/变更语义和完整遍历。
- 不用页码漂移造成漏/重并静默计算全量。

### ARC-010-C007｜速率限制

- 限制按身份、端点、任务和供应商配额，返回剩余/重试信息。
- 限流不得映射为空结果；高风险绕过需批准。

### ARC-010-C008｜超时重试

- 区分连接/读取/总体超时，只有幂等或有幂等键操作按退避重试。
- 每次attempt保存，最终状态区分未知/部分/失败。

### ARC-010-C009｜错误码

- 错误分类认证、授权、输入、对象、来源、冲突、限流、超时、内部和不可用。
- 错误不泄露秘密/内部路径，也不把未知映射200成功。

### ARC-010-C010｜原始响应保存

- 外部关键响应保存原始字节、头、状态、时间、端点、TLS、哈希和解析关系。
- 标准化JSON/表格不能替代原始响应。

### ARC-010-C011｜字段精度

- 金额/费率/高度/时间使用无损类型、原生单位、精度和转换规则。
- 禁止浮点静默舍入；格式化值与计算值分开。

### ARC-010-C012｜时区

- 机器时间使用UTC/明确格式，保留链时间和原始时区/精度。
- 禁止无时区日期或把区块时间当采集时间。

### ARC-010-C013｜地址格式

- 地址绑定链/网络、编码、大小写/校验和、原始值与规范化值。
- 不跨链仅按字符串合并；无法验证时拒绝/保留原值。

### ARC-010-C014｜大文件上传

- 分块上传定义会话、顺序、大小、总哈希、断点、配额、超时和完成原子性。
- 未完成/哈希失败对象保持隔离，不进入证据区。

### ARC-010-C015｜恶意文件扫描

- 上传在隔离区完成类型、压缩、宏/脚本、恶意内容和沙箱策略。
- 扫描失败/未知不自动放行；原始对象仍受控保全。

### ARC-010-C016｜回调验证

- 回调验证端点、TLS、签名、时间、nonce、事件ID、顺序和重放。
- 回调只触发候选状态，关键变更需主动核验/复核。

### ARC-010-C017｜供应商SLA

- 契约明确可用性、限流、错误、变更、历史范围、事件和支持。
- SLA达标不证明数据准确，失败触发降级/替代而非默认继续。

### ARC-010-C018｜兼容性

- 消费者/提供者矩阵覆盖版本、字段新增/删除、枚举、精度、错误和历史对象。
- 未知字段应保留/忽略策略明确，不能误解。

### ARC-010-C019｜弃用策略

- 提前通知范围、替代、日期、迁移、监控和最后支持版本。
- 使用中任务/历史重现依赖未处理前不得删除旧契约。

### ARC-010-C020｜契约测试

- 正向、边界、无权限、签名、重放、分页、限流、超时、错误、精度、文件和兼容均覆盖。
- Mock通过不能替代真实受控供应商/端点验证。

## 6. 响应包络

响应至少包含request/correlation、status、data或error、schema/api version、source、observed_at、partial/truncated、warnings和原始响应对象引用。禁止用空数组同时表示“无结果”和“查询失败”。

## 7. 数据与审计

接口调用形成SourceRecord/ToolRecord/CustodyEvent或审计事件；业务响应不返回不必要个人信息、秘密或内部安全细节。

## 8. 主要风险与控制

|风险|控制|停止|
|---|---|---|
|latest语义漂移|明确版本|版本未知|
|令牌等于授权|任务/目的授权|范围不符|
|重试重复写|幂等键|冲突负载|
|分页漏数|稳定游标|快照不明|
|限流变空|错误显式化|部分响应|
|金额浮点|无损精度|舍入不明|
|回调伪造|签名/重放|验证失败|

## 9. 记录

契约、版本、Schema、示例、认证授权、测试、原始响应、供应商变更、兼容和弃用记录按QMS-002保存。

## 10. 验收准则

- [ ] 版本/契约/安全/错误完整；
- [ ] 幂等、分页、限流、超时/重试可验证；
- [ ] 原始响应、精度、时区和地址无损；
- [ ] 文件/回调/供应商接口隔离；
- [ ] 兼容与弃用保护历史重现；
- [ ] 当前API部署数量为0。

## 11. 当前结论

接口契约已形成候选标准，未实现或部署任何生产API。

供应商文档、Mock和契约示例只能支持设计评审，不能证明真实端点在目标版本、权限与数据范围内可用。

## 12. 架构决策与接口约束

- [ ] 接口清单、数据流和主体批准；
- [ ] OpenAPI/等效契约与ARC-004对象一致；
- [ ] 安全、幂等、错误和原始响应通过测试；
- [ ] 供应商真实端点与Mock分别验证；
- [ ] 兼容、弃用、回滚和历史重现演练。

P0字段不得nullable/默认值掩盖；接口不得直接接收或返回客户资产私钥；每次跨边界必须有任务/授权/对象/密级/关联上下文。
