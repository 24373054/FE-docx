# 节点与外部数据源治理架构

## 1. 文件目的

定义自建全/归档/裁剪节点、第二客户端、第三方RPC、区块浏览器、原始区块文件、官方页面和商业标签库的来源等级、身份、版本、同步、最终性、响应留存、差异和替换规则。

## 2. 当前状态

- 自建/归档/裁剪节点和批准第三方服务均为0；
- 公开探针出现过交易数冲突，已证明单一公共来源不足；
- Bitcoin创世原始字节是候选GT2，不是完整链能力；
- EVM/TRON尚无同等级原始对象包；
- 任何来源须同时满足授权、许可、完整性、语义和可复现性。

## 3. 来源等级

|等级|来源|允许用途|
|---|---|---|
|DS1|冻结原始协议字节/官方可核验制品|关键事实基础|
|DS2|受控自建节点/第二客户端|独立解析与复核|
|DS3|经批准RPC/官方API|采集与交叉核对|
|DS4|浏览器/项目页面|导航、展示、线索|
|DS5|商业标签/聚类|候选推断|

低等级不能静默替代高等级；来源等级不替代具体质量评价。

## 4. 数据源记录

每个来源登记主体、端点/制品、链/网络、版本、许可、数据范围、历史深度、身份/证书、限流、错误、保留、变更、状态和替代。

## 5. 详细控制要求

### ARC-006-C001｜数据源分级

- 每项来源按DS1至DS5登记，并记录适用事实、禁止用途和复核要求。
- 来源实际能力变化时重新分级。

### ARC-006-C002｜自建全节点

- 全节点按网络/客户端/配置/同步/最终性/权限受控。
- 节点自建不自动证明客户端无错误或数据完整。

### ARC-006-C003｜归档节点

- 需要历史状态时应验证归档模式、历史范围、状态查询和存储完整性。
- 普通全节点不能被假定支持任意历史状态。

### ARC-006-C004｜裁剪节点

- 记录裁剪策略、可用历史、重建依赖和不支持查询。
- 裁剪节点不得用于缺失数据的关键历史事实。

### ARC-006-C005｜第二客户端

- 第二实现应独立来源/解析路径，并冻结版本、配置和比较字段。
- 同一API包装或同一上游不构成独立客户端。

### ARC-006-C006｜第三方RPC

- 记录端点、供应商、认证、请求、响应、限流、错误、TLS和时间。
- 不作为P0唯一来源；返回成功不等于语义正确。

### ARC-006-C007｜区块浏览器

- 页面/API输出仅作为DS4，保存快照、URL、时间和字段解释。
- 不用UI聚合值替代原始区块/交易解析。

### ARC-006-C008｜原始区块文件

- 保存原始字节、获取方式、长度、哈希、网络身份和解析记录。
- 文本hex与解码字节均有对象身份，不因换行变化静默改变。

### ARC-006-C009｜官方项目页面

- 官方页面用于协议、版本、升级或地址信息线索，保存发布日期与快照。
- 页面说明需与实际客户端/链数据交叉核对。

### ARC-006-C010｜商业标签库

- 标签保留来源、许可、证据、对象、时间、置信、冲突和版本。
- 不透明标签/聚类不能独立证明自然人身份或违法属性。

### ARC-006-C011｜节点身份

- 核验链ID、网络ID、创世对象、客户端握手/同伴和预期网络。
- 身份冲突立即隔离。

### ARC-006-C012｜客户端版本

- 记录名称、版本、制品哈希、构建来源、补丁和已知缺陷。
- 自动更新或版本未知时停止受控用途。

### ARC-006-C013｜同步高度

- 记录高度/插槽、区块哈希、观察时间、落后量和比较来源。
- 高度相同哈希不同或落后超过门限时标记异常。

### ARC-006-C014｜finalized/safe语义

- 每条链明确safe/finalized/确认数的协议与客户端语义。
- 不把“latest”或一次确认当成不可逆。

### ARC-006-C015｜链重组监测

- 监测同高度哈希变化、回退深度、分叉和受影响对象。
- 重组对象重新确认，历史报告影响进入QMS-009。

### ARC-006-C016｜限流与错误

- 保存状态码、应用错误、重试、退避、配额和部分响应。
- 限流/超时不得被默认空结果或0值掩盖。

### ARC-006-C017｜TLS证书

- 对HTTPS来源记录主机、证书链/指纹、有效期和验证结果。
- 禁止为连通性跳过证书验证；证书不证明数据内容正确。

### ARC-006-C018｜响应留存

- 原始请求/响应、头、时间、来源、哈希和解析输出成套留存。
- 仅保存解析表或截图不足以复核P0。

### ARC-006-C019｜多源差异

- 按字段、对象、版本、时间、语义和来源等级比较，保留所有差异。
- P0差异未解释时输出冲突/无法判断并阻断发布。

### ARC-006-C020｜停用与替换

- 许可、可靠性、安全、变更或退出触发停用，记录历史依赖。
- 替代来源需重新准入、回归和适用性确认。

## 6. 来源选择

先选择回答问题所需最高等级原始来源，再选独立复核来源和辅助展示来源。不得因成本/速度先用低等级并把缺口后补。

## 7. 差异工作流

冻结对象/时间 → 保存所有原始响应 → 核验网络/版本/语义 → 独立解析 → 确定来源故障/时间差/重组/未知 → 限制/阻断 → CAPA与历史影响。

## 8. 主要风险与控制

|风险|控制|停止|
|---|---|---|
|公共端点错误|多源/原始字节|P0冲突|
|伪独立来源|上游/实现核验|共享依赖|
|历史状态缺失|归档核验|查询不支持|
|错误最终性|链语义|对象未稳定|
|标签越界|DS5/证据层|身份强结论|
|限流变空|错误显式化|响应不完整|

## 9. 记录

来源登记、许可、请求响应、节点快照、版本、TLS、差异、停用和替代记录按QMS-002保存。

## 10. 验收准则

- [ ] 来源分级与用途明确；
- [ ] 自建/外部/第二客户端独立性可核验；
- [ ] 网络、版本、同步、最终性和重组受控；
- [ ] 请求响应完整留存；
- [ ] P0差异阻断；
- [ ] 当前来源批准数量保持0。

## 11. 当前结论

数据源治理已形成草案，但只有公开候选包；正式验证须补自控/独立来源。

## 12. 架构决策与接口约束

- [ ] 每链来源组合和等级批准；
- [ ] 原始对象、第二实现和辅助来源分工明确；
- [ ] 最终性/重组规则冻结；
- [ ] 错误、限流、TLS和留存契约通过；
- [ ] 停用、替代与历史影响可执行。

来源接口必须返回source_id/version/network、request/response object、observed_at、height/hash/finality、error/retry、TLS和content hash；缺失不得默认。
