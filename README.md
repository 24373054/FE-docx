# 区块链电子数据取证与关联分析研发项目

> 当前阶段：**研究与研发准备**
>
> 当前可依赖基线：监管准入研究、市场竞争研究和文档成熟度登记
>
> 当前不可宣称：生产就绪、司法鉴定执业能力、CMA/CNAS能力、已验证区块链专项方法
>
> 项目接管日期：2026-07-29

## 1. 项目定位

本项目研究在中国大陆既有电子数据司法鉴定制度内建设区块链相关技术能力，并探索边界清晰的技术服务。

项目关注：

1. 公开链及经合法授权电子数据的提取、固定和关联分析；
2. Bitcoin、Ethereum/EVM、TRON等代表性链的数据与协议事实；
3. 链上路径、跨链、合约、标签和聚类结果的可复现性与解释边界；
4. 司法鉴定登记、CMA、CNAS、北京地方要求和电子证据规则；
5. To G、To B、To C用户的真实任务、采购路径和合规红线；
6. 方法、人员、设备、数据、质量和运行记录的长期能力建设。

本仓库以文档研究和研发管理为主，不包含产品代码开发。

### 2.3 v3.0.0处置

原v3.0.0曾被标注为“生产单一权威版本”。2026年7月29日审计发现：

- 92份文档被统一标为受控基线，16份模板被统一标为受控模板；
- 绝大多数批准人、版本和生效日期没有签批记录支持；
- 1631项需求、1631项控制和1631项测试全部标为approved；
- 1631项测试使用同一条通用预期，且没有实际执行证据；
- 生产就绪检查项均未勾选；
- 多数核心文档具有同构章节和重复控制话术。

因此，v3.0.0的生产声明已撤销。原文件保留为需求线索和重构输入，统一进入“历史生成稿（待重构）”或“模板草案（待实测）”状态。

“单一权威”只描述同一主题不应存在相互冲突的现行文件，不代表未经签批和实证的内容自动生效。

## 3. 法律与业务边界

- 未取得司法鉴定机构和司法鉴定人登记前，不以本机构名义受理或出具司法鉴定意见。
- 未取得相应CMA或CNAS能力前，不使用相关标志或作误导性宣传。
- CMA、CNAS、司法行政登记和诉讼证据审查是不同制度，不能相互替代。
- 链上事实不能单独证明自然人身份、主观故意、资金违法属性、资产权属或法律责任。
- 地址标签、聚类、跨链和混币分析必须区分事实、规则命中、统计推断、主体归属意见和法律判断。
- 第三方RPC、区块浏览器和商业标签库不是关键事实的当然唯一来源。
- 不提供私钥保管、资产托管、兑换、撮合、定价、代收代付或资产处置。
- 不承诺解冻、追回、立案、采信或办案期限。
- AI/Agent可辅助检索、候选生成、证据索引和一致性检查，不独立形成或批准最终结论。

更完整的准入判断见[`区块链电子数据司法鉴定与技术服务准入研究基线`](01-regulatory/11-authority-verified-entry-baseline.md)。

## 7. 自动质量检查

```bash
python scripts/build_document_index.py --check
python scripts/repo_quality_check.py
python scripts/validate_traceability.py
python scripts/validate_internal_links.py
```

这些检查能够发现元数据、编号、最低结构、重复内容、JSON解析、路径、链接和映射错误。

这些检查不能证明：

- 法律结论正确；
- 标准条款已满足；
- 方法或工具有效；
- 人员胜任；
- 测试已经执行；
- 质量体系已经运行；
- 文档已经由公司批准；
- 项目可以生产交付。

## 8. 当前阶段门

当前位于G0“研究立项与问题验证”。

进入G1“范围与验证设计冻结”至少需要：

- [ ] 项目发起人具名批准治理状态规则与禁止事项；
- [ ] 主管机关书面答复关键准入问题，或批准保守替代路径；
- [ ] 完成至少24个有效客户访谈和反证分析；
- [ ] 选定不超过三个初始技术任务；
- [ ] 每个任务形成方法确认计划、样本计划和数据合规评估；
- [ ] 确定责任人、独立复核人、预算上限和退出条件；
- [ ] 旧文档中与首批任务有关的条款完成逐项重构；
- [ ] 不存在把文档数量、自动检查或采购预算当作能力证明的决策。

在G1通过前，不启动正式受案、重资产实验室采购或大范围系统建设。
