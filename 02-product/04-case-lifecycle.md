# 任务生命周期与受控状态机

## 1. 文件目的

定义研究任务、技术服务任务和未来获准司法鉴定任务的状态、迁移、责任与证据。

系统状态描述工作进度，不替代法定程序状态。

## 2. 状态设计原则

- 状态只由有权角色按前置证据迁移；
- 进入下一状态不删除历史；
- 暂停、拒绝、撤回和重开是一等状态；
- 技术完成不等于质量通过或批准；
- 发布不等于交付，交付不等于归档；
- 到期不会自动销毁存在保全的数据；
- 所有异常迁移必须说明理由。

## 3. 主状态流

```text
线索 -> 预审 -> 已受理 -> 采集中 -> 采集完成 -> 分析中
 -> 待方法复核 -> 待质量复核 -> 待批准 -> 已发布
 -> 已交付 -> 已归档 -> 已销毁
```

旁路状态：

```text
任一活动态 -> 已暂停 / 已拒绝 / 已撤回
已归档或已撤回 -> 已重开
```

## 4. 详细控制要求

|控制ID|主题|进入条件|离开条件/禁止|
|---|---|---|---|
|PRD-004-C001|线索状态|仅保存最小联系和需求信息|不得导入案件材料或承诺受理|
|PRD-004-C002|预审状态|主体、问题、权限、数据和边界进入审查|结论为补充、受理或拒绝|
|PRD-004-C003|已受理|合同/委托、范围、人员、方法候选和数据门批准|未满足法定/合同前提不得进入|
|PRD-004-C004|采集中|采集会话、对象、人员和环境已授权|失败和异常全部登记后结束|
|PRD-004-C005|采集完成|对象清单、哈希、来源和交接核对|缺关键对象时只能暂停/补采|
|PRD-004-C006|分析中|冻结工作副本、方法和工具版本|不得修改原始对象|
|PRD-004-C007|待方法复核|分析输出、假设、反例和运行包完整|执行人不能自我复核|
|PRD-004-C008|待质量复核|方法差异关闭且报告候选完整|记录/授权/P0缺陷未关阻断|
|PRD-004-C009|待批准|技术和质量复核完成，残余风险明确|批准人不能无证据放行|
|PRD-004-C010|已发布|版本冻结、签署、包和撤回门已批准|不得原位改写|
|PRD-004-C011|已交付|接收方、渠道、容器哈希和回执核对|无回执不得视为交付|
|PRD-004-C012|已归档|交付、保管、留存和访问条件完整|归档后写入需重开|
|PRD-004-C013|已暂停|记录触发、影响、临时控制和恢复条件|不得继续受限活动|
|PRD-004-C014|已拒绝|明确合法性、能力、材料或范围理由|不得复制任务绕过拒绝|
|PRD-004-C015|已撤回|错误、越权、污染或监管变化触发|通知和影响分析未完不能关闭|
|PRD-004-C016|已重开|新证据、纠错、规则变化或合法请求获批|生成新版本并保留原链|
|PRD-004-C017|已销毁|期限届满且无保全/争议，销毁获批并验证|不得删除销毁证明|
|PRD-004-C018|状态迁移权限|角色—状态—条件矩阵获批|无权限、共享账号迁移阻断|
|PRD-004-C019|状态冻结|P0、保全、事件或争议冻结关联对象和迁移|只有具名解除决定可恢复|
|PRD-004-C020|超时升级|每状态设置服务目标、依赖和升级|不得自动跳级或批准|

全部控制当前为`not_implemented`。

## 5. 线索与预审

线索阶段只保留：

- 联系渠道；
- 请求主体类型；
- 高层问题；
- 预计链/数据类型；
- 是否涉及真实资产、冻结、RWA或敏感数据；
- 下一步授权。

预审形成：

- 主体和授权判断；
- 可回答技术问题；
- 报告类型；
- 监管、数据和金融边界；
- 能力/人员/工具可用性；
- 补充材料；
- 受理、拒绝或暂缓建议。

不得先上传材料再补授权。

## 6. 受理与采集

已受理必须有版本化范围。

采集阶段每个会话：

1. 校验任务状态；
2. 校验授权和人员；
3. 锁定方法、工具和环境；
4. 记录开始时间；
5. 保存原始结果和失败；
6. 计算完整性值；
7. 生成会话清单；
8. 结束并交接。

采集完成只表示输入已冻结，不表示足够回答问题。

## 7. 分析与复核

分析状态允许：

- 规范化；
- 确定性复算；
- 按获批规则生成候选路径；
- 登记标签、假设、反例和差异；
- 形成报告候选。

待方法复核时禁止继续无记录修改结果。

若复核失败：

- 退回分析；
- 暂停等待补充；
- 拒绝无法回答；
- P0问题触发状态冻结。

## 8. 批准、发布与交付

### 批准

批准输入包括：

- 委托和范围；
- 证据包；
- 方法/工具状态；
- 方法与质量复核；
- 数据和披露审查；
- 已知限制和残余风险；
- 撤回与更正安排。

### 发布

发布生成不可变版本号、内容哈希、签署记录和包引用。

### 交付

交付记录接收方身份、渠道、时间、容器哈希、对象数、异常和回执。

## 9. 暂停、拒绝和撤回

|触发|状态|最低动作|
|---|---|---|
|授权不清|暂停|停止处理并请求书面澄清|
|任务越界|拒绝|保留原因和已收材料处置|
|来源冲突|暂停|冻结受影响结果并复核|
|方法P0错误|撤回/暂停|影响所有关联任务|
|数据泄露|冻结/撤回|事件响应和通知评估|
|客户要求非法活动|拒绝|记录但不提供规避方案|
|规则或许可失效|暂停/撤回|查找历史交付并评估|

## 10. 重开

重开必须建立：

- 原任务和版本引用；
- 重开原因与请求人；
- 新证据或规则；
- 授权和范围复核；
- 历史报告影响；
- 新责任人、期限和状态；
- 是否通知原接收方。

重开不能把历史记录改为“从未发生”。

## 11. 归档与销毁

归档包至少含：

- 状态事件链；
- 授权、对象和保管记录；
- 方法、工具和环境；
- 分析、复核和批准；
- 报告、交付和回执；
- 暂停、差异、缺陷和更正；
- 留存/保全条件；
- 未来复现说明。

销毁前再次查询保全、投诉、诉讼、监管和合同限制。

## 12. 用户故事与验收示例

### 12.1 授权失效自动冻结

作为质量负责人，我需要授权到期时阻止任务继续。

- [ ] 系统识别授权期限；
- [ ] 到期任务进入状态冻结；
- [ ] 采集、分析和发布写权限撤销；
- [ ] 已生成结果不删除；
- [ ] 责任人收到升级通知；
- [ ] 新授权经复核后才能恢复。

### 12.2 已发布报告撤回

作为批准人，我需要在P0方法错误影响历史报告时启动撤回。

- [ ] 受影响版本和接收方可定位；
- [ ] 原报告保持不可变并标记撤回；
- [ ] 原因、影响和临时措施记录；
- [ ] 接收方通知和回执保存；
- [ ] 修正版形成新版本；
- [ ] 方法、工具和历史任务联动处理。

## 13. 状态事件字段

每次迁移至少记录：

- event ID；
- from/to状态；
- 请求人、执行人和批准人；
- 时间与时区；
- 条件检查结果；
- 证据对象和批准引用；
- 原因和备注；
- 自动/人工来源；
- 失败尝试；
- 关联通知。
