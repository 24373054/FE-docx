# 产品发布与验收准则

## 1. 文件目的

规定文档、Schema、方法、工具、模型、数据和未来产品能力的发布与验收门。

Git提交、自动检查或演示通过不等于公司批准或生产发布。

## 2. 发布类型

|类型|对象|最低批准|当前状态|
|---|---|---|---|
|文档基线|政策、需求、方法、程序|责任人复核和具名批准|仅草案/研究|
|数据/Schema|manifest、目录、迁移|兼容、样本和回退验证|Schema草案|
|方法|范围、算法、样本和报告|方法/质量/授权人员|0个方法V1|
|工具|制品、依赖和配置|工具验证、安全和发布|0个批准工具|
|模型/规则|版本、数据、性能和解释|用例、风险和偏差评审|0个批准模型|
|验证发布|样本、真值和证据包|样本/复核/质量批准|0个批准样本|
|产品试验|集成功能和受控环境|G1/G2、人员和数据批准|未开始|
|生产发布|真实任务完整基线|G3及全部前置|禁止|

## 3. 验收原则

- 验收针对明确版本、范围和环境；
- 需求、控制、测试和证据闭合；
- 正常、失败和拒绝路径同等重要；
- 预期结果在执行前冻结；
- 测试必须保留实际输出；
- P0/P1缺陷不以计划压力豁免；
- 已知限制进入发布声明；
- 回滚在发布前验证；
- 发布后监测和撤回可执行。

## 4. 详细控制要求

|控制ID|主题|验收要求|未满足状态|
|---|---|---|---|
|PRD-009-C001|需求追踪覆盖|每个发布范围需求对应控制、测试和证据|缺口阻断|
|PRD-009-C002|单元测试|确定性函数/规则覆盖正常、边界和失败|not_executed不计通过|
|PRD-009-C003|集成测试|对象、方法、数据源、权限和报告接口真实连接|模拟接口差异须声明|
|PRD-009-C004|端到端测试|从授权到交付/归档完整运行并保留对象链|只测界面不合格|
|PRD-009-C005|黄金样本回归|使用批准样本、冻结预期、版本和容差|候选真值不可作发布门|
|PRD-009-C006|方法边界验证|覆盖适用、边界、超范围、冲突和拒绝|只测成功路径阻断|
|PRD-009-C007|工具验证|功能、正确性、版本、环境、失败和安全完成|供应商声明不替代|
|PRD-009-C008|安全测试|身份、权限、隔离、接口、秘密、日志和漏洞测试|高危问题未关阻断|
|PRD-009-C009|性能测试|代表性负载、硬件、分位、资源和降级行为|无基线不得承诺SLA|
|PRD-009-C010|灾备演练|空环境恢复对象、配置、权限和关键业务|纸面方案不算执行|
|PRD-009-C011|数据迁移验证|计数、哈希、引用、兼容和回退核对|静默丢失/改义阻断|
|PRD-009-C012|文档同步|用户、运行、方法、安全和限制与制品版本一致|旧文档禁止发布|
|PRD-009-C013|模板同步|报告、记录和包模板字段/状态与Schema一致|空字段不得假装完成|
|PRD-009-C014|培训完成|具名人员按角色通过培训、评价和授权|仅参加培训不够|
|PRD-009-C015|权限复核|发布前逐任务/角色核验最小权限和服务账号|共享账号/超权阻断|
|PRD-009-C016|回滚演练|恢复旧版、数据和配置并验证兼容|不可回滚需重大风险批准|
|PRD-009-C017|已知缺陷接受|缺陷有影响、临时控制、期限和有权批准|P0及证据错误不得接受|
|PRD-009-C018|发布批准|批准人、范围、版本、证据和时间完整|口头或自批无效|
|PRD-009-C019|发布后监测|观察窗、指标、责任、告警和退出条件明确|无监测不关闭发布|
|PRD-009-C020|撤回阈值|P0错误、越权、污染、重大漏洞或监管禁止可立即撤回|无法定位受影响版本阻断|

全部控制当前为`not_implemented`，测试均为`not_executed`。

## 5. 发布候选包

每个候选包包含：

- release ID、类型、版本和状态；
- 范围与排除项；
- 需求和变更；
- 制品、配置、数据和Schema；
- 方法、工具、规则和模型；
- 测试计划、冻结预期和实际结果；
- 缺陷、偏离和残余风险；
- 安全、隐私、监管和许可审查；
- 培训与权限；
- 部署/分发和回滚；
- 监测和撤回；
- 编制、复核和批准。

候选包自身计算哈希并归档。

## 6. 测试证据

每次执行至少记录：

- test ID和版本；
- requirement/control链接；
- 样本/输入对象及哈希；
- 环境、工具和依赖；
- 前置条件；
- 冻结预期；
- 实际步骤、输出和日志；
- 差异与缺陷；
- 执行人和复核人；
- 时间；
- pass/fail/blocked/not_executed；
- 关联证据包。

`blocked`和`not_executed`不得计为passed。

## 7. 分层测试

### 7.1 确定性核心

- 字节解析；
- 哈希和签名验证；
- 金额和费用；
- 规范化；
- 资产变化守恒；
- 时间/单位转换；
- 包校验。

### 7.2 推断和规则

- 真阳性/假阳性/真阴性/假阴性；
- 边界和冲突；
- 数据漂移和规则变化；
- 对抗样本；
- 解释一致性；
- 拒绝输出。

### 7.3 全流程

- 授权；
- 采集；
- 分析；
- 盲复核；
- 报告；
- 交付；
- 归档；
- 更正/撤回；
- 历史复现。

## 8. 缺陷等级

|等级|示例|发布动作|
|---|---|---|
|P0|原始证据被改写、错误强结论、越权、秘密泄露|停止并撤回|
|P1|关键功能/复核/恢复失败|阻断|
|P2|有限场景缺陷且有可验证替代|具名接受后可限范围|
|P3|低影响易用性/文档问题|排期并声明|

证据错误不得仅因“低频”降级。

## 9. 发布门

候选进入发布批准前：

- [ ] 范围和版本冻结；
- [ ] 需求追踪100%有处置状态；
- [ ] 所有P0/P1测试实际执行并通过；
- [ ] 正常、边界、冲突、恶意和回归覆盖；
- [ ] 监管、数据、安全和许可评审完成；
- [ ] 人员具名授权且职责分离；
- [ ] 证据包和历史复现通过；
- [ ] P0/P1缺陷为0；
- [ ] 文档、模板和培训同步；
- [ ] 回滚、监测和撤回可执行。

当前没有候选满足该门。

## 10. 回滚与撤回

回滚面向可恢复的技术/配置版本。

撤回面向已经分发但不再可依赖的制品、方法或报告。

两者均记录：

- 触发；
- 影响范围；
- 决定人；
- 停止时间；
- 对象和版本；
- 数据兼容；
- 通知；
- 实际结果；
- 恢复/替代决定。

## 11. 发布后观察

观察指标至少覆盖：

- 完整性差异；
- 授权/权限异常；
- 解析和方法错误；
- 来源冲突；
- 性能与资源；
- 复核差异；
- 报告更正/投诉；
- 安全事件；
- 备份/恢复；
- 外部规则或链变化。

观察期结束需要具名决定，不能自动关闭。

## 12. 用户故事与验收示例

### 12.1 方法候选被阻断

作为发布经理，我需要在黄金样本仍为`truth_prepared`时阻止方法V1发布。

- [ ] 系统读取样本状态；
- [ ] `truth_prepared`不等于approved；
- [ ] 测试状态保持blocked/not_executed；
- [ ] 发布审批不可提交为通过；
- [ ] 显示缺少的独立复核和批准；
- [ ] 阻断记录进入候选包。

### 12.2 P0缺陷触发撤回

作为质量负责人，我需要在金额解析错误时撤回受影响版本。

- [ ] 版本、任务、报告和接收方可查询；
- [ ] 停止进一步发布；
- [ ] 原制品保持可审计；
- [ ] 通知和回执保存；
- [ ] 修复后回归不覆盖旧结果；
- [ ] 管理层决定恢复或终止。
