# 追踪目录

本目录保存需求、控制、测试和证据模板映射；其中原v3.0.0候选项已经过本轮文档重构和逐条评审，但没有因此获得公司批准或进入执行。

当前1639组记录只证明需求已完成内容评审且ID闭合，不证明需求已经批准、控制已经实施、测试已经执行或证据已经产生。

|文件|行数（不含表头）|当前状态|用途|
|---|---:|---|---|
|`requirements.csv`|1639|`reviewed`|已完成内容评审、仍待公司批准的需求及责任、优先级|
|`controls.csv`|1639|`not_implemented`|待批准、实施和验证的控制|
|`tests.csv`|1639|`not_executed`|主题化正向/反向预期；仍须形成具体步骤、输入和实际结果|
|`traceability.csv`|1639|无执行状态|需求—控制—测试—模板—文档映射|

状态升级要求：

- 需求变为`reviewed`前，必须完成去重、来源核验和可测试性检查；变为`approved`前还必须取得公司具名批准；
- 控制变为`implemented`或`verified`前，必须明确实施对象、责任人、频次和实际记录；
- 测试变为`passed`、`failed`或`blocked`前，必须有具体输入、步骤、判定、实际结果、执行人、时间和证据位置；
- `evidence_template`只表示候选记录模板，不是实际证据记录。

修改文档中的控制主题时，同步更新目录并运行：

```bash
python scripts/validate_traceability.py
```
