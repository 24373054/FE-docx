# Bitcoin UTXO采集与资金追踪方法

## 1. 文件目的

建立Bitcoin区块、交易、脚本、输入输出、UTXO、确认、重组、找零和CoinJoin分析的证据级方法。

本文件是生产体系中的单一权威来源。与旧版本、会议纪要、原型界面或口头约定不一致时，除非存在经批准的变更单，否则以本文件及其引用的受控记录为准。

## 2. 适用范围

### 2.1 纳入范围

- Bitcoin UTXO采集与资金追踪方法涉及的研发、验证、运行和质量活动
- 对外技术服务前的内部评审与批准
- 相关人员、工具、数据、场所和供应商的受控管理

### 2.2 明确排除

- 替代司法行政、市场监管、法院、检察机关或公安机关的法定判断
- 未经授权的数据获取、身份调查、交易撮合或资产处置
- 将概率性分析包装为自然人身份、违法属性或法律责任的确定结论

## 3. 角色与职责

- **文件责任人（Bitcoin方法负责人）**：维护本文件的准确性、可执行性和变更记录。
- **批准人（质量负责人）**：确认范围、风险、资源和对外承诺边界。
- **质量负责人**：验证本文件是否与质量手册、记录控制和审计要求一致。
- **执行人员**：仅在授权范围内操作，发现前提不成立时立即停止并升级。
- **独立复核人员**：不得直接复制执行人员的结论，应重新核对证据链和关键计算。

## 4. 核心原则

1. 原始证据不可覆盖；修订、派生和展示对象必须保持独立身份。
2. 链上技术事实、规则推断、统计推断、主体归属意见和法律判断分层表达。
3. 第三方RPC、区块浏览器和商业标签库只能作为辅助来源，不能成为关键事实的唯一依据。
4. AI或Agent只能执行受控检索、候选生成和一致性检查，不得独立批准最终结论。
5. 任何结果都必须能够指向输入、工具版本、参数、环境、执行人、复核人和适用方法。
6. 证据不足、来源冲突或方法越界时，系统应输出事实缺口、候选集合或无法判断。

### M-BTC-001-C001｜网络与链身份

- **控制目的**：在Bitcoin UTXO采集与资金追踪方法中，使“网络与链身份”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：“网络与链身份”应被拆分为可验证步骤；每一步都要指定责任角色、前置条件、执行记录、异常分支和完成定义。
- **输入条件**：“网络与链身份”的输入至少包含原始对象或正式记录、采集时间、数据源等级、当前版本以及前序环节的通过证据。
- **执行记录**：“网络与链身份”不得只保存最终截图；应同时保存机器可读结果、过滤条件、排序规则、失败尝试和人工复核批注。

- **责任角色**：Bitcoin方法负责人负责“网络与链身份”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

## 12. 方法验证矩阵

|验证维度|最低设计|接受原则|失败处置|
|---|---|---|---|
|准确性|使用独立真实值样本比较关键字段、金额和关系|确定性字段不得存在无法解释的错误|暂停方法并分析解析、数据源或规则原因|
|精密度|同一人员重复、不同人员重复和不同环境重复|差异应在预先定义范围内且可解释|限制适用范围或改进操作规程|
|稳健性|改变非关键参数、节点实现、数据规模和异常输入|方法不得在未告知情况下改变结论等级|增加输入检查、错误处理或拒绝条件|
|边界与反例|覆盖空值、极值、冲突、攻击和相似但非目标场景|误报、漏报和拒绝率有记录|修正规则或明确禁用场景|
|长期复现|使用冻结制品、依赖和样本重跑历史版本|可得到等价结果并解释环境差异|保留兼容环境或迁移验证器|

### 结论等级

1. **F1可验证技术事实**：可直接由原始链数据、密码学验证或明确记录复现。
2. **I1规则推断**：基于已验证规则，必须说明前提、反例和误差。
3. **I2统计推断**：必须报告样本、模型、阈值和不确定性。
4. **A1主体归属意见**：需要链外身份、设备、账户或正式回函形成闭环，不能仅由链上模式生成。
5. **L1法律判断**：不属于系统自动输出和普通技术分析范围。
