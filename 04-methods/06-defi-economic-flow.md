# DeFi协议交互与经济流重建方法

## 1. 文件目的

定义去中心化交易、流动性、借贷、质押、包装和闪电贷场景中，如何从冻结的链上执行对象重建协议动作和资产分录。

本方法区分“调用了某入口”“执行产生某事件”“账户资产发生某变化”“取得某种经济结果”和“具有某种法律性质”。

当前没有获批DeFi协议配置、真值样本、状态重放环境、净变化闭合案例或方法确认报告，运行数为0。

## 2. 范围与排除

### 2.1 候选范围

- AMM交换、路由器和聚合器多跳；
- 流动性添加/移除及LP Token；
- 借贷、还款、抵押和清算；
- 质押、领取奖励、包装/解包；
- 闪电贷及同交易偿还；
- 手续费、滑点、Token税、rebase和失败调用；
- 按地址/资产/交易建立整数资产分录。

### 2.2 排除

- 依据协议名称或UI状态直接认定经济实质；
- 只凭事件名断言标准动作；
- 把报价、预估、模拟或pending结果当实际执行；
- 未经独立估值方法输出法币损益、市场操纵或获利结论；
- 把合约调用地址等同协议控制人、受益人或自然人；
- 对复杂策略自动给出违法属性、合同关系或清算责任。

## 3. 协议配置

每个协议、网络、合约版本和功能必须有配置：

|项目|最低内容|
|---|---|
|身份|网络、协议名称、官方来源、部署地址、代码哈希|
|拓扑|入口、路由器、池、vault、oracle、Token和实现合约|
|版本|生效高度、升级事件、治理参数和历史代码|
|动作|调用selector、事件、状态变化和失败语义|
|资产|合约、标准、decimals、包装/份额/债务关系|
|数学|费率、舍入、份额、指数、价格单位和边界|
|例外|Token税、rebase、回调、hook、代理和非标准实现|
|输出|可确认事实、候选动作、未知项和禁止措辞|

配置未获批时，只输出通用调用和资产分量，不输出协议动作名称。

## 4. 角色与运行前提

|角色|职责|
|---|---|
|DeFi方法负责人|维护协议配置、经济分录规则和验证设计|
|链级方法负责人|确认交易、收据、trace、状态和代码P0事实|
|执行人员|冻结对象、运行分录和记录差额|
|独立复核人员|按同一冻结对象重建动作与净变化|
|质量负责人|检查反例、估值边界、协议升级和措辞|

历史状态、trace或代码能力不足时，必须缩小问题，不得以浏览器摘要补齐。

|M-DEFI-001-C020|Rebase|余额/份额变化须绑定rebase或指数机制和观察区块，不把无转账变化误作资金流|状态快照、规则|只按Transfer重建|
|M-DEFI-001-C021|失败调用|失败交易、内部revert和部分调用按执行语义保留；报价/模拟不当成已执行|收据、trace|过滤失败导致路径缺口|
|M-DEFI-001-C022|资产净变化|按地址、资产和交易汇总所有可得分录并执行平衡检查；未闭合项显式列出|分录账、差额|强制将差额归零|
|M-DEFI-001-C023|协议语义证据|动作名称须由版本化代码/ABI、官方规范、事件、调用和状态共同支持|语义证据包|仅凭供应商标签命名|

## 6. 标准工作流程

### 6.1 D0 任务与问题

登记目标交易/地址、协议、区块、要回答的动作和净变化问题，以及不得回答的法律问题。

### 6.2 D1 链级对象固定

按链级方法固定交易、收据、日志、trace、历史代码、状态差异和区块锚。

### 6.3 D2 协议版本选择

通过目标高度的地址、实现、代码哈希和治理参数选择协议配置。无法选择时停止动作命名。

### 6.4 D3 调用树与事件

建立调用顺序、入口、回调、池、Token和事件对象；原始对象与ABI解码分开。

### 6.5 D4 原子分录

按每次原生币/Token/份额/债务变化建立整数分录，保留地址角色和对象引用。

### 6.6 D5 动作组合

把满足协议规则的分录组合成swap、add/remove liquidity、borrow、repay等候选动作，并保留未匹配分录。

### 6.7 D6 费用与差额

分解费用、Token税、舍入、rebase和未知差额，执行按资产平衡检查。

### 6.8 D7 替代解释

检查聚合器、多跳、代理、回调、失败分支、内部账本、同交易对手和非标准Token。

### 6.9 D8 独立复核

复核人员从冻结对象重建分录与动作，不以执行人员动作标签作为唯一输入。

### 6.10 D9 输出

分别输出执行事实、协议动作候选、资产净变化、未知差额、估值边界和限制。

## 7. 分录模型

每个分录至少包含：

```text
entry_id / sequence
chain / block / transaction / call_path / log_index
from_address / to_address / protocol_role
asset_contract / asset_type
amount_integer / decimals / amount_display
entry_kind
source_object_id / derivation_rule
execution_status / fact_level / value_status
```

`entry_kind`可为transfer、mint、burn、debt_increase、debt_decrease、share_mint、share_burn、fee或unknown。

分录是技术记账模型，不自动等同会计分录、所有权转移或法律上的给付。

## 8. 净变化与价值

### 8.1 净变化

按同一资产身份计算：

`净变化 = 确认流入 - 确认流出 + mint - burn + 其他已证明状态变化`

若存在Token税、rebase、遗漏trace、内部余额或非标准hook，则输出已知分量及未闭合差额。

### 8.2 估值

本方法不默认计算法币价值。若引用oracle、DEX价格、成交均价或外部市场价格，必须单独记录来源、时点、单位、流动性和操纵风险。

### 8.3 收益

单次净流入不等于利润。成本基础、融资、链外付款、未实现头寸和主体范围缺失时，拒绝“获利”结论。

## 9. 失败与停止条件

必须停止强结论：

- 协议或合约版本不能确认；
- 交易/收据/trace/历史状态不能闭合；
- 调用轨迹被裁剪或事件与状态冲突；
- 非标准Token行为导致分录不平；
- 份额、债务、指数或decimals使用了当前值替代历史值；
- 估值来源、时点或单位不明；
- 结果要求身份、动机、非法性或法律关系判断。

停止后仍报告可验证分录和缺口。

## 10. 输出最低集

```text
run_id / protocol_id / protocol_version
chain / block / transaction / execution_status
entry_contract / selector / implementation / code_hash
action_candidate / action_rule / action_status
pool_or_market / position_id / debt_id
asset / amount_integer / decimals / amount_display
share_or_debt_amount / index_or_ratio / ratio_block
fee_components / slippage_basis / token_tax_candidate
net_change_known / unexplained_difference
valuation_source / valuation_time / valuation_status
fact_level / value_status / method_version / tool_id
input_object_ids / alternative_explanations / limitation
```

## 11. 记录与关联接口

|记录|最低内容|
|---|---|

|链级证据包|交易、收据、trace、状态、代码和区块锚|
|调用树|顺序、入口、回调、池、Token和失败节点|

|动作决策|组合规则、替代解释和候选等级|
|差额记录|费用、税、rebase、舍入和未知|
|复核记录|独立重建、差异和处置|

## 12. 方法验证矩阵

|维度|正向样本|反向/边界样本|接受原则|当前状态|
|---|---|---|---|---|
|协议版本|单版本及升级前后|仿冒地址、代理切换|按高度选择规则|未执行|
|swap|单池、多跳、聚合器|失败、最小输出未满足、同额无关转账|逐跳可追溯|未执行|
|流动性|添加、移除、份额变化|不同比例、费用、当前比例误用|基础资产与份额分开|未执行|
|借贷清算|借款、还款、部分清算|代还、超额、坏账、失败|债务和支付不混用|未执行|
|质押奖励|stake/unstake/claim|accrued未领取、锁定、复投|状态与实际取得分开|未执行|
|包装/闪电贷|包装往返、原子借还|回调失败、未还、Token税|闭环或明确缺口|未执行|
|非标准Token|税、rebase、hook|伪事件、decimals变化|不强制平账|未执行|
|净变化|完整trace与状态|裁剪trace、内部账本|已知与未知分开|未执行|
|复现性|第二人员重建|不同客户端/解析器|P0无未解释差异|未执行|

## 13. 当前证据与限制

- 获批协议配置：0；
- 冻结DeFi对象包：0；
- 获批动作真值样本：0；
- 完整状态重放：0；
- 非标准Token反例：0；
- 资产净变化闭合案例：0；
- 独立复核、方法和人员批准：0。

当前不得声称具备DeFi经济流完整还原或收益认定能力。

## 15. 外部依据

- 每个协议配置须引用协议官方规范、部署登记、验证代码、ABI和治理/升级记录；
- EVM基础对象遵循目标网络的官方RPC、交易和收据规则；
- 第三方分析、价格聚合器和协议UI只作为辅助资料；
- 历史分析必须保存目标区块适用的配置和代码，不得只链接当前网页；
- 外部资料在方法批准和重大升级前重新核验并冻结。
