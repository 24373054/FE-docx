# 地址标签与实体归属证据方法

## 1. 文件目的

定义地址标签、地址用途和实体归属意见的来源分级、证据固定、冲突处理、有效期、撤回和报告引用规则。

标签是带来源、范围、时点和强度的主张，不是地址固有属性。机构、账户、钱包、服务用途、使用人和控制人必须分别记录。

当前没有获批标签源、商业供应商、主体回函、链上签名挑战、设备取证或实体归属结论；生产标签数为0。

## 2. 范围与排除

### 2.1 候选范围

- 官方公告、主体回函、链上签名、设备取证和交易所/机构流水；
- 公开网页、商业供应商和社区标签；
- 来源快照、证据等级、首次发现、最后验证和有效期；
- 冲突标签、实体范围、地址用途和控制/使用区别；
- 自然人/机构归属的不同证据门；
- 标签撤回、历史影响和报告引用。

### 2.2 排除

- 未经合法授权向平台、个人或主管机关查询；
- 抓取需要登录、绕过访问控制或违反许可的数据；
- 以聚类、交易模式或同名Token直接确认主体；
- 把KYC材料、账户流水或设备数据扩大用于其他目的；
- 用“官方”“交易所”“涉案”“风险”等名称暗示法律结论；
- 把供应商置信分转写为自然人控制事实。

## 3. 标签主张模型

每条标签必须是独立、可撤回的主张：

```text
claim_id
network_id / address / address_type
claim_type
claim_value
entity_id / entity_type
scope
valid_from / valid_to / observed_at
source_id / source_type / source_object_id
evidence_level
verification_method / verifier
conflict_status / review_status
supersedes / withdrawn_reason
```

同一地址可以同时存在“某服务充值地址”“某账户曾使用”“某机构公开收款地址”等不同主张，不得覆盖成一个永久名称。

## 4. 证据等级

|等级|来源示例|可支持范围|主要限制|
|---|---|---|---|
|L0|未核验社区线索、搜索结果|发现线索|高误报、易过期|
|L1|可固定公开网页、供应商标签|公开声明或供应商主张|不证明控制|
|L2|主体正式回函、官方地址清单|回函范围内机构用途|需核验主体与有效期|
|L3|受控签名挑战、设备/账户证据、完整流水|特定时点的使用或控制证据|授权、密钥范围和共享使用限制|
|L4|多类独立证据闭合并由有权人员批准|明确限定的A1归属意见|仍非法律责任结论|

等级不是自动分数。来源真实性、对象范围和时间不满足时可降级或拒绝。

## 5. 详细控制要求

|控制ID|主题|强制规则|最低证据|阻断条件|
|---|---|---|---|---|
|M-LABEL-001-C001|来源类型|每个来源登记主体、渠道、许可、获取方式、原始格式、可信边界和用途|来源登记|来源匿名或许可不明|
|M-LABEL-001-C002|官方公告|核验发布主体、官方域名/渠道、文件身份、发布时间和明确地址范围；“官方”不等于当前控制|网页/文件快照|转述或截图无法定位原文|
|M-LABEL-001-C003|主体回函|回函须有查询范围、主体身份、授权签署、地址、用途、时段和保留意见|正式回函、核验记录|非授权人员或范围含糊|
|M-LABEL-001-C004|链上签名|使用一次性挑战、域、地址、网络、时间和验证算法；签名只证明对应密钥参与该挑战|挑战、签名、复算|重放、域不明或规则未验证|
|M-LABEL-001-C005|设备取证|仅引用合法取得且保管链完整的密钥/钱包/日志证据，区分存在、使用和控制时点|设备证据引用、授权|来源/保管链或最小必要性失败|
|M-LABEL-001-C006|交易所流水|核对平台、账户、地址、币种/链、时段、导出完整性和正式回函；流水不自动证明实际使用人|原始导出、回函|只有用户截图或摘要|
|M-LABEL-001-C007|公开网页|保存HTML/PDF/截图、URL、获取时间、哈希和上下文；动态页需声明不可重现部分|来源快照|只保存搜索摘要|
|M-LABEL-001-C008|商业供应商|登记产品、版本、方法说明、数据日期、许可、置信语义、覆盖和撤回机制|供应商档案|无法导出来源或版本|
|M-LABEL-001-C009|社区标签|只能作为L0/L1候选，保留提交者/平台声明、时间和交叉核验，不进入强归属|线索记录|匿名标签被直接采用|
|M-LABEL-001-C010|来源快照|每次使用冻结原始来源对象、元数据、字节数和哈希；后续变化形成新版本|证据包|只留可变URL|
|M-LABEL-001-C011|证据等级|按来源、身份、范围、时间、独立性和冲突逐项判定，不以来源数量简单投票|分级表|相互复制来源被当独立|
|M-LABEL-001-C012|首次发现|记录首次发现时点、来源和当时内容，不反推地址此前已属该实体|历史记录|发现日被当生效起点|
|M-LABEL-001-C013|最后验证|每次复核记录实际步骤、结果、人员和证据对象，不用自动更新时间伪装验证|复核记录|只刷新时间戳|
|M-LABEL-001-C014|有效期|按来源稳定性、用途和风险设置复核期限；过期标签保留历史但默认不用于强结论|有效期规则|过期标签无提示继续使用|
|M-LABEL-001-C015|冲突标签|并列保存冲突原值、来源、范围和时间；未解决前不得多数投票选一|冲突单|覆盖或删除异议|
|M-LABEL-001-C016|实体范围|区分法律主体、品牌、业务线、服务、账户、钱包、地址簇和地址，不把层级向上扩张|实体模型|品牌标签直接映射法人|
|M-LABEL-001-C017|地址用途|充值、提现、热钱包、归集、合约、手续费等用途须有时段和来源；用途可变化|用途主张|用途被写成永久属性|
|M-LABEL-001-C018|控制与使用区别|分别记录生成、持有密钥、签名、操作账户、受益和受托等关系，不用“属于”概括|关系主张|证据只支持使用却称控制|
|M-LABEL-001-C019|自然人归属|须有合法链下身份闭环、具体地址/时段、独立复核和高风险批准；链上模式不足|A1证据包|只有聚类、标签或资金流|
|M-LABEL-001-C020|机构归属|须核验机构身份、正式声明/流水/签名、业务范围和时段；服务客户地址不自动归机构控制|机构证据包|仅因与机构地址交互|
|M-LABEL-001-C021|标签撤回|来源撤回、过期、冲突、投诉或错误触发停用、历史影响、下游通知和保留原记录|撤回单、影响清单|删除记录而无审计轨迹|
|M-LABEL-001-C022|报告引用|报告展示主张、等级、来源、时点、范围、冲突和限制；不得只显示醒目名称/颜色|报告抽查|来源和边界不可见|

## 6. 标准工作流程

### 6.1 L0 任务登记

登记地址、网络、所需主张类型、目的、授权、最小必要性和允许证据等级。

### 6.2 L1 来源获取

通过批准渠道取得原始材料，记录访问条件、响应、错误、页面/文件和哈希。

### 6.3 L2 来源身份

核验发布/回函主体、域名、签署授权、供应商版本或设备证据链。

### 6.4 L3 主张抽取

只抽取来源明确说出的地址、实体、用途、时段和限定，不补写控制关系。

### 6.5 L4 地址与网络核验

验证地址格式、网络、合约/账户类型和来源中的表示；同字节跨链地址不自动合并。

### 6.6 L5 证据分级

按来源直接性、身份、范围、时间、独立性和完整性判定L0至L4候选等级。

### 6.7 L6 冲突检查

搜索既有主张、撤回、用途变化和独立反证。冲突未解决时保留并列状态。

### 6.8 L7 独立复核

复核人员从原始来源重新抽取，核对是否把品牌、服务、账户、使用和控制混淆。

### 6.9 L8 批准与发布

只有授权用途所需等级达到门槛后才可发布；自然人归属须额外合规和高风险批准。

### 6.10 L9 监控与撤回

到期、来源更新、供应商撤回、投诉或新证据触发复核和下游影响评估。

## 7. 主张类型

|claim_type|含义|示例边界|
|---|---|---|
|publicly_declared_address|主体公开声明地址|只限声明内容和时段|
|service_deposit_address|服务充值用途|不等于服务自有资产|
|service_withdrawal_address|服务提现/热钱包候选|不等于所有输出收款人|
|account_used_address|某账户曾使用|不等于账户持有人独占控制|
|device_observed_address|设备中观察到|不等于设备所有人签署全部交易|
|signature_verified_address|挑战签名验证|只证明相应密钥参与挑战|
|institution_control_candidate|机构控制候选|须说明链下闭环和限制|
|person_control_candidate|自然人控制候选|高风险A1，不能自动产生|

## 8. 冲突与有效期

### 8.1 冲突类型

- 同一地址被不同实体主张；
- 同一实体的地址用途变化；
- 供应商与官方来源冲突；
- 链上签名与回函范围冲突；
- 平台账户与设备证据指向不同使用者；
- 地址从个人钱包转入托管/合约角色。

冲突状态为`open`时，默认阻断强归属。

### 8.2 有效期

有效期是内部复核门，不是事实自然失效日。过期后历史主张保留，但新报告需重新验证。

## 9. 隐私与访问控制

- 链上地址公开不代表可以无限关联个人信息；
- 自然人材料按敏感/受限数据处理；
- 标签库按案件、用途和最小权限分区；
- 对外披露前复核来源许可、必要性和潜在伤害；
- 供应商不得获得无必要的客户案件地址全集；
- 查询、查看、导出和撤回必须进入审计日志。

## 11. 记录与关联接口

|记录|最低内容|
|---|---|
|来源登记|主体、渠道、许可、版本、用途和可信边界|
|来源快照|原始对象、URL/文件、时间、哈希和获取日志|
|主张记录|地址、实体、用途、关系、时段和证据等级|
|冲突记录|全部主张、来源、影响、决定和复核日期|
|签名挑战|随机挑战、域、时间、签名、算法和复算|
|撤回记录|原因、下游运行/报告、通知和保留证据|
|报告引用|主张、等级、来源、范围、冲突和限制|

## 12. 方法验证矩阵

|维度|正向样本|反向/边界样本|接受原则|当前状态|
|---|---|---|---|---|
|官方来源|可验证公告和地址清单|仿冒域名、转述、页面更新|来源身份和快照闭合|未执行|
|主体回函|授权签署且范围明确|非授权回复、模糊品牌范围|不超出回函|未执行|
|签名挑战|已知密钥受控签名|重放、错链、错域、格式错误|只证明挑战范围|未执行|
|设备/流水|受控设备和完整导出|用户截图、共享设备、账户代用|使用与控制分开|未执行|
|供应商/社区|有版本和来源链|匿名、过期、相互复制|不得直接升级强归属|未执行|
|有效期|用途稳定与变化样本|撤回、转移、过期|历史与当前分开|未执行|
|冲突|可解决和不可解决冲突|多数来源互相抄袭|原值并列并可阻断|未执行|
|实体范围|法人、品牌、服务、账户分层|同名机构、客户地址|不向上扩张|未执行|
|复现性|第二人员从原始来源抽取|页面不可用、格式变化|差异有记录|未执行|

## 13. 当前证据与限制

- 获批标签来源：0；
- 商业供应商合同与方法证据：0；
- 主体正式回函：0；
- 链上签名挑战：0；
- 设备/账户流水授权样本：0；
- 获批自然人或机构归属：0；
- 方法、工具和人员批准：0。

当前不得把仓库中的市场/机构研究名单或公共标签当成生产地址归属库。

## 14. 生效前检查

- [ ] 来源类型、证据等级和用途门获批；
- [ ] 官方、回函、签名、设备/流水、供应商和社区样本覆盖；
- [ ] 地址网络、实体范围、用途和控制关系Schema通过；
- [ ] 冲突、过期、撤回和下游通知演练；
- [ ] 自然人归属的法律依据和高风险批准流程建立；
- [ ] 供应商许可、版本、来源和退出机制审查；
- [ ] 隐私影响、最小必要性和访问审计通过；
- [ ] 第二人员独立抽取复核；
- [ ] 报告展示来源、时点和限制；
- [ ] 方法、工具、人员和用途获批。

## 15. 外部依据

- 官方公告和主体回函须保存原始文件/页面和发布身份证据；
- 商业供应商须提供可审计的版本、来源类别、置信语义、更新/撤回和许可说明；
- 社区数据遵循其许可和可核验范围，不得抓取或再发布受限个人信息；
- 电子签名、设备和账户材料的使用须由具体任务授权和适用法律意见支持；
- 外部来源现行性至少按本文件复核周期及每次高风险报告前重新核验。
