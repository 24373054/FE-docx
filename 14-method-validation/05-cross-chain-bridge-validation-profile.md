# 跨链桥关联方法验证剖面

## 文件定位

按桥逐一验证锁定、销毁、消息、证明、铸造、释放、退款、延迟、聚合和批处理，不允许以统一时间金额近似替代协议证据。

## 适用范围

- 适用于研发立项、设计评审、方法确认、工具验证、试点、采购、人员授权和准入材料准备。
- 不适用于代替主管机关解释、个案法律结论或未经授权的调查活动。
- 与v1文件冲突时，以本文件中更严格且有权威来源支持的要求为内部研发控制；涉及外部许可的事项仍以主管机关书面意见为准。

## 权威依据与使用规则

- **ETH-RPC**：[Ethereum JSON-RPC API](https://ethereum.org/developers/docs/apis/json-rpc/)。使用方式：登记发布日期、访问日期、适用条款、是否现行和对本项目的约束；正式申报前重新核验。
- **TRON-EVENT**：[TRON Developer Documentation: Event Log](https://developers.tron.network/docs/event)。使用方式：登记发布日期、访问日期、适用条款、是否现行和对本项目的约束；正式申报前重新核验。
- **NIST-CFTT**：[NIST Computer Forensics Tool Testing Program](https://www.nist.gov/programs-projects/computer-forensics-tool-testing-cftt)。使用方式：登记发布日期、访问日期、适用条款、是否现行和对本项目的约束；正式申报前重新核验。
- **FATF-2025**：[FATF 2025 Targeted Update on Virtual Assets and VASPs](https://www.fatf-gafi.org/en/publications/Fatfrecommendations/targeted-update-virtual-assets-vasps-2025.html)。使用方式：登记发布日期、访问日期、适用条款、是否现行和对本项目的约束；正式申报前重新核验。

> 来源分级：法律/行政法规/部门规章和官方办事指南优先；标准全文以合法获得的正式文本为准；协议事实优先使用官方客户端、规范和节点实测；论文与商业材料只能作为研究线索。

## 全局结论边界

- 本文件属于研发与准入准备文件，不构成司法行政、市场监管、法院、检察机关或公安机关对具体能力范围的预先认可。
- 未取得司法鉴定机构和司法鉴定人登记前，不以本机构名义出具司法鉴定意见；未取得相应CMA或CNAS能力前，不使用相关标志。
- 链上技术事实、规则推断、统计推断、主体归属意见和法律判断必须分层表达，任何模块不得将概率结果自动升级为确定事实。
- 第三方区块浏览器、商业RPC和标签库只能作为辅助来源；关键事实应由自建节点、独立客户端、原始区块解析或密码学证明进行复核。
- AI/Agent只可执行受控检索、候选生成、证据索引和一致性检查，不得独立形成最终技术结论。
- 任何涉及个人信息、敏感个人信息、案件秘密、商业秘密或跨境数据的处理，必须先完成合法性、最小必要性和访问授权审查。

## 详细控制要求

本节将能力拆成46项可审计控制。每项控制均应进入需求、设计、验证、培训和变更管理链路。

### V2-VAL-005-C001｜桥版本登记
- **目标**：将“桥版本登记”转化为可执行、可复核、可度量的能力，避免仅以界面展示、模型分数或供应商声明替代技术证明。
- **实现要求**：系统必须记录桥版本登记的输入、来源、授权、时间、版本、参数、运行环境、输出及其与“源链合约”的派生关系；不可覆盖原始记录。
- **验证要求**：使用正常样本、边界样本、冲突样本、恶意样本和历史回归样本验证；至少由另一名未参与实现的人员按记录独立复现。
- **验收证据**：需求追踪记录，并附机器可读结果、人工复核意见、失败样本、已知限制和适用范围。
- **阻断条件**：输入来源无法追溯或授权不明时阻断；阻断后只能输出事实缺口、候选集合或无法判断，不得以默认值继续生成确定性结论。
- **责任角色**：技术负责人主责，质量负责人批准进入受控基线；任何例外必须有编号、期限、补偿控制和关闭证据。

## 评审问题

- 该能力回答的技术问题是否清楚，是否混入主体身份或法律性质判断？
- 每个输出能否追溯到原始证据、工具版本、参数和运行环境？
- 对协议升级、链重组、节点分叉、供应商中断和标签冲突是否有预案？
- 验证样本是否独立于开发样本，是否包含失败与拒绝场景？
- 人员授权是否基于培训、见证操作、盲测和持续能力监控？
- 数据是否满足合法、正当、必要、最小化、分区和期限控制？
- 报告措辞能否让非技术审查者理解依据、限制和反例？
- 变更后是否能识别受影响案件、模型、数据和报告？
