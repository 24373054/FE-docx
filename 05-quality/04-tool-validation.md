# 软件与取证工具验证程序

## 1. 文件目的

规定自研工具、开源工具、商业工具、脚本、数据库和AI组件的预期用途、版本、环境、测试、缺陷、批准与停用。

本文件是生产体系中的单一权威来源。与旧版本、会议纪要、原型界面或口头约定不一致时，除非存在经批准的变更单，否则以本文件及其引用的受控记录为准。

## 2. 适用范围

### 2.1 纳入范围

- 软件与取证工具验证程序涉及的研发、验证、运行和质量活动
- 对外技术服务前的内部评审与批准
- 相关人员、工具、数据、场所和供应商的受控管理

### 2.2 明确排除

- 替代司法行政、市场监管、法院、检察机关或公安机关的法定判断
- 未经授权的数据获取、身份调查、交易撮合或资产处置
- 将概率性分析包装为自然人身份、违法属性或法律责任的确定结论

## 3. 角色与职责

- **文件责任人（测试负责人）**：维护本文件的准确性、可执行性和变更记录。
- **批准人（质量负责人）**：确认范围、风险、资源和对外承诺边界。
- **质量负责人**：验证本文件是否与质量手册、记录控制和审计要求一致。
- **执行人员**：仅在授权范围内操作，发现前提不成立时立即停止并升级。
- **独立复核人员**：不得直接复制执行人员的结论，应重新核对证据链和关键计算。

## 4. 核心原则

1. 原始证据不可覆盖；修订、派生和展示对象必须保持独立身份。
2. 链上技术事实、规则推断、统计推断、主体归属意见和法律判断分层表达。
3. 第三方RPC、区块浏览器和商业标签库只能作为辅助来源，不能成为关键事实的唯一依据。
4. AI或Agent只能执行受控检索、候选生成和一致性检查，不得独立批准最终结论。
5. 任何结果都必须能够指向输入、工具版本、参数、环境、执行人、复核人和适用方法。
6. 证据不足、来源冲突或方法越界时，系统应输出事实缺口、候选集合或无法判断。

## 5. 详细控制要求

### QMS-004-C001｜工具登记

- **控制目的**：在软件与取证工具验证程序中，使“工具登记”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：“工具登记”应被拆分为可验证步骤；每一步都要指定责任角色、前置条件、执行记录、异常分支和完成定义。
- **输入条件**：“工具登记”的输入至少包含原始对象或正式记录、采集时间、数据源等级、当前版本以及前序环节的通过证据。
- **执行记录**：“工具登记”不得只保存最终截图；应同时保存机器可读结果、过滤条件、排序规则、失败尝试和人工复核批注。
- **验收证据**：以受控记录与哈希清单证明“工具登记”已经执行；仅有会议纪要、口头确认或界面截图不构成充分证据。
- **阻断条件**：出现“来源、授权或对象身份无法确认”，或“工具登记”的关键输入无法回溯时，停止强结论并创建异常记录。
- **责任角色**：测试负责人负责“工具登记”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

### QMS-004-C002｜预期用途

- **控制目的**：在软件与取证工具验证程序中，使“预期用途”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：对“预期用途”的判断不得仅依赖界面展示或供应商结论，关键事实应能够回溯至原始对象、协议字段或受控记录。
- **输入条件**：进入“预期用途”环节前，应确认案件状态允许、所需数据完整、依赖工具已批准且不存在未关闭的P1不符合。
- **执行记录**：完成“预期用途”时，执行人应登记正常路径和异常路径，特别说明数据源切换、重试、舍入、排除和降级行为。
- **验收证据**：设计评审记录；证据必须直接显示“预期用途”的输入、实际输出、复核差异和最终处置。
- **阻断条件**：如果关键字段在独立来源间冲突且无法解释，则“预期用途”只能输出事实缺口或候选集合，不得自动降级数据源后继续。
- **责任角色**：质量负责人负责“预期用途”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

### QMS-004-C003｜供应商声明

- **控制目的**：在软件与取证工具验证程序中，使“供应商声明”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：实施“供应商声明”时应优先保证可重现性和证据完整性，而不是追求最大覆盖率；无法满足前提时输出拒绝结论。
- **输入条件**：对于“供应商声明”，执行人需先列出要验证的事实、允许使用的数据源和不能回答的问题，复核人确认后开始。
- **执行记录**：执行记录应逐步说明如何处理“供应商声明”，保存实际命令、API参数、原始响应或表单字段，并记录每次人工选择的理由。
- **验收证据**：至少提交一份与“供应商声明”对应的方法确认报告，并附正常、边界和失败样本的对象ID及哈希。
- **阻断条件**：当“供应商声明”超出已验证方法范围、复核无法重现或工具版本、参数或运行环境未锁定时，必须阻断发布。
- **责任角色**：技术负责人负责“供应商声明”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

### QMS-004-C004｜源码或二进制来源

- **控制目的**：在软件与取证工具验证程序中，使“源码或二进制来源”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：“源码或二进制来源”发生变更后，应重新执行影响分析、回归验证和人员授权确认，历史案件是否受影响必须形成书面结论。
- **输入条件**：处理“源码或二进制来源”前，必须取得与该主题直接相关的对象ID、来源ID、授权记录、适用方法版本和执行人员授权。
- **执行记录**：系统需为“源码或二进制来源”生成唯一运行ID，将输入对象、输出对象、工具制品哈希、参数快照、开始结束时间和异常事件绑定。
- **验收证据**：验收包包含“源码或二进制来源”的工具验证报告、独立重算结果、异常记录和适用范围声明。
- **阻断条件**：发现方法超出已验证范围后，隔离“源码或二进制来源”相关结果，评估对当前和历史案件的影响，再决定返工或撤回。
- **责任角色**：方法负责人负责“源码或二进制来源”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

- **强制要求**：“版本与哈希”的验收必须包含正常、边界、冲突、恶意和历史回归样本，并由未参与实现的人员独立复核。
- **输入条件**：“版本与哈希”的输入至少包含原始对象或正式记录、采集时间、数据源等级、当前版本以及前序环节的通过证据。

- **验收证据**：以操作日志与录像索引证明“版本与哈希”已经执行；仅有会议纪要、口头确认或界面截图不构成充分证据。
- **阻断条件**：出现“无法由第二人员按记录复现”，或“版本与哈希”的关键输入无法回溯时，停止强结论并创建异常记录。
- **责任角色**：安全负责人负责“版本与哈希”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

- **责任角色**：项目负责人负责“依赖锁定”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

- **首要动作**：固定“AI模型版本变化”发生时的原始状态、日志和版本，暂停可能覆盖证据的自动操作。
- **分析重点**：区分与“AI模型版本变化”直接相关的可验证事实、待验证假设和替代解释。
- **允许输出**：已验证事实、证据缺口、候选关系及其适用条件。
- **禁止输出**：超出证据支持程度的主体身份、违法属性、主观故意或法律责任结论。
- **关闭证据**：针对“AI模型版本变化”形成复核记录、纠正措施、回归测试或书面确认。

## 9. 记录与留存

|记录|最低内容|责任人|触发时点|
|---|---|---|---|
|软件与取证工具验证程序执行记录|对象、来源、授权、步骤、工具、参数、结果和异常|测试负责人|每次执行|
|软件与取证工具验证程序复核记录|独立检查范围、差异、结论、签名和时间|独立复核人员|结果发布前|
|变更记录|原因、影响、验证、批准、回退和历史案件评估|文件责任人|任何基线变化|
|例外记录|范围、期限、风险、补偿控制和关闭证据|质量负责人|偏离标准时|
|培训授权|课程、考核、授权范围、有效期和撤销记录|人员负责人|首次授权及续期|

## 10. 验收准则

- [ ] 软件与取证工具验证程序中的每项强制要求均映射到需求、控制和至少一个测试用例。
- [ ] 执行人员可仅依据本文件和受控表单完成软件与取证工具验证程序相关流程，不依赖未记录的口头知识。
- [ ] 至少一名独立人员能够复现关键结果并解释差异。
- [ ] 失败路径、拒绝结论和异常升级机制经过演练。
- [ ] 关联脚本、模板、接口和目录链接均通过自动检查。
- [ ] 不存在未完成占位、失效路径或未经批准的对外承诺。

## 12. 审核证据与抽样策略

|审核对象|抽样规则|必须查看的证据|判定重点|
|---|---|---|---|
|受控文件|每类至少一份，重大变更全部抽查|批准记录、旧版撤回、查新记录|文件与实际是否一致|
|案件或项目记录|风险分层抽样，高风险与异常案件全查|授权、采集、哈希、复核、交付和异常|记录是否同期形成且可重现|
|人员授权|关键角色和到期授权全查|资格、培训、考核、授权范围|实际操作是否在授权内|
|工具与方法|生产使用版本全覆盖|验证计划、样本、结果、缺陷和批准|验证是否覆盖实际用途|
|CAPA|重复问题和逾期事项全查|根因、措施、有效性验证|是否真正防止复发|

审核不得仅检查“文件存在”。审核员应抽取一个真实输出，反向追踪到原始对象、人员、工具、方法和批准记录。
