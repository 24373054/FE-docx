# 区块链电子数据取证与关联分析研发项目章程

## 1. 章程目的

定义项目使命、范围、治理边界、阶段门、资源原则、成功标准、退出和终止条件。

项目研究在中国大陆电子数据司法鉴定制度下建设区块链专项能力，并探索边界清晰的技术服务；不自创“区块链司法鉴定”资质类别。

本章程尚未获公司具名批准。当前阶段为G0研究与研发准备，不授权真实受案、对外鉴定、生产系统、资产服务或能力宣传。

## 2. 使命、价值与范围

### 2.1 使命

以可复算原始对象、可审计保管链、经确认方法和边界清晰的技术解释，降低区块链电子数据在受理、固定、分析、复核和报告中的错误与越界风险。

### 2.2 双轨范围

|轨道|目标|当前允许|当前禁止|
|---|---|---|---|
|A 合规技术服务|研究可由普通技术服务主体提供的证据固定、技术分析与工具支持|公开研究、模拟验证、用户访谈准备|越权受案、鉴定意见、资产控制|
|B 准入研究|研究司法鉴定登记、CMA/CNAS及合作路径|主管机关问题包和资质差距分析|未取得资质前作能力承诺|

### 2.3 技术优先级

第一阶段只覆盖Bitcoin、EVM/Ethereum与TRON的确定性对象和失败路径；跨链、DeFi、混币、聚类、标签、合约和AI仅在各自验证门后逐项释放。

## 3. 当前事实与成功定义

当前：

- 主管机关书面答复：0；
- 用户访谈和付费试点：0；
- 方法V1、获批工具、人员、节点和样本：0；
- 真实案件、生产部署和对外报告：0；
- 文档、公开研究和模拟证据包已形成，但不证明运行能力。

项目成功不能用文档数衡量。至少要同时形成：

1. 可执行的准入或合作结论；
2. 真实用户问题及付费/采购证据；
3. 获批真值、方法、工具、人员和质量记录；
4. 合法、可复核且可停止的受限试点；
5. 管理层按阶段门继续投入的决定。

## 4. 治理结构与阶段门

|阶段|核心问题|通过证据|当前|
|---|---|---|---|
|G0 研究立项|是否值得继续研究|章程、监管/市场基线、授权包|进行中，未签批|
|G1 范围冻结|做什么、谁负责、预算多少|监管答复/法律意见、访谈、责任人、验证计划|未通过|
|G2 方法验证|结果是否可复算|GT、工具、方法V1、独立复核、质量批准|未通过|
|G3 受限试点|能否在合法边界交付|合作/授权、人员、系统、质量运行和试点记录|未通过|
|G4 准入/规模化|能否正式进入目标制度/市场|登记/认可/合同/生产能力|未通过|
|G5 持续运行|能力是否持续受控|监控、内审、管理评审、能力验证和改进|不适用|

任何阶段不得用下一阶段的预期收入倒推本阶段通过。

## 5. 详细控制要求

|控制ID|主题|强制规则|最低证据|阻断条件|
|---|---|---|---|---|
|GOV-001-C001|使命与价值主张|使命限定为合法电子数据技术研究、能力建设和可解释输出，不承诺结果、资质或资产追回|批准章程、对外表述表|价值主张含无证据能力|
|GOV-001-C002|0301/0302优先范围|准入研究先围绕电子数据具体事项向主管机关确认，不自创分类或默认覆盖0303/0304|范围清单、咨询记录|分类依据或边界不明|
|GOV-001-C003|首批链范围|Bitcoin、EVM/Ethereum、TRON分别建立网络、对象、样本和方法门；新增链另行变更|验证计划、样本矩阵|因客户请求直接扩链|
|GOV-001-C004|证据级成功标准|以真值、复现、错误、拒绝、保管链和批准证据衡量，不以截图、演示或文档数量替代|阶段证据包|关键结果无独立证据|
|GOV-001-C005|阶段门授权|每个G门由有权管理层基于清单签批；未通过只可执行前一阶段允许活动|决议、签批页|口头同意或倒签|
|GOV-001-C006|对外承诺边界|宣传、合同、演示和沟通须与真实资质、方法、系统和人员状态一致|审查记录、批准文案|出现鉴定/CMA/CNAS或生产误导|
|GOV-001-C007|资源优先级|G1前仅释放低成本、可取消、无真实案件的资源；重资产和长期合同后置|预算决议、采购单|不可取消承诺提前发生|
|GOV-001-C008|试点退出条件|试点须预定义合规、方法、质量、安全、客户和经济停止条件及数据退出|试点方案、退出记录|没有可执行停止/删除路径|
|GOV-001-C009|重大风险升级|准入、数据、资产、P0错误、安全、人员独立和对外误导风险立即升级|风险/事件记录|风险被业务负责人单方接受|
|GOV-001-C010|项目终止条件|监管否定、无有效需求、验证不可达、风险不可接受或资源不匹配触发终止评审|终止评审、资产处置|沉没成本成为继续理由|
|GOV-001-C011|利益相关方沟通|按管理层、监管、用户、合作方和研发受众提供不同且一致的事实、限制和行动请求|沟通计划、版本记录|同一状态多套互相冲突表述|
|GOV-001-C012|年度目标冻结|目标须绑定基线、责任人、预算、证据和阶段门；未批准字段保持空白|年度目标表、决议|用未经批准目标考核或宣传|

## 6. 决策与资源原则

### 6.1 优先级

1. 合法性和数据授权；
2. 证据完整性与P0正确性；
3. 人员独立和质量运行；
4. 用户价值与可采购性；
5. 扩链、自动化和规模。

优先级冲突时，前项拥有停止权。

### 6.2 资源释放

|阶段|可释放|不得释放|
|---|---|---|
|G0|公开研究、文档、模拟样本、咨询准备|真实案件、长期平台、实验室重资产|
|G1|批准的咨询、访谈、小额验证资源|无退出条款采购|
|G2|受控节点、工具、样本与独立验证|未经确认的对外交付|
|G3|严格范围试点|规模化宣传和无边界合同|

## 7. 沟通与报告

- 项目发起人向管理层报告阶段、风险、预算和待决策项；
- 合规负责人控制监管和法律表述；
- 方法/质量负责人报告验证证据与失败；
- 商务人员只使用批准的能力表述；
- 任何人发现状态夸大可直接向质量负责人和项目发起人升级；
- 报告必须同时列已完成、未完成、数量为0的关键能力和下一门槛。

## 8. 主要风险与控制

|风险|后果|控制|当前|
|---|---|---|---|
|准入路径错误|投资和宣传越界|书面咨询、法律意见、双轨|开放|
|技术服务触及虚拟资产禁止活动|合同/刑民事风险|负面清单、逐案审查|开放|
|文档成熟度被冒充能力|错误签约或受案|状态、阶段门、禁止声明|高|
|公共/商业数据错误|P0结论错误|原始对象、真值、冲突停止|已证实风险|
|人员不独立|复核无效|具名任命、授权、利益冲突|开放|
|采购沉没|项目被锁定|G1前可取消资源|开放|
|真实数据提前进入|隐私与保管链失败|G3前禁止、数据门|开放|

## 9. 记录与审查

最低记录：

- 章程及每次修订；
- G0至G5决议和证据索引；
- 年度目标、预算和资源释放；
- 利益相关方沟通版本；
- 风险、例外、终止和退出记录；
- 项目资产、数据和知识产权处置。

章程每年至少评审一次；重大监管、主体、商业或方法事实变化时立即评审。

- [ ] 公司主体、发起人和批准机构具名；

- [ ] 对外表述、数据负面清单和资产服务禁区获批；
- [ ] G1证据、会议日期和决策模板确认；
- [ ] 终止、数据删除、合同退出和资产处置可执行；
- [ ] 本章程与GOV-009、GOV-010无冲突。
