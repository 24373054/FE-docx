# 文档层级与单一权威来源

## 1. 文件目的

建立政策、标准、方法、SOP、表单、记录和外来文件的层级关系，消除v1/v2并行、摘要文件冒充完整基线和口头约定覆盖正式文件的问题。

本文件是生产体系中的单一权威来源。与旧版本、会议纪要、原型界面或口头约定不一致时，除非存在经批准的变更单，否则以本文件及其引用的受控记录为准。

## 2. 适用范围

### 2.1 纳入范围

- 文档层级与单一权威来源涉及的研发、验证、运行和质量活动
- 对外技术服务前的内部评审与批准
- 相关人员、工具、数据、场所和供应商的受控管理

### 2.2 明确排除

- 替代司法行政、市场监管、法院、检察机关或公安机关的法定判断
- 未经授权的数据获取、身份调查、交易撮合或资产处置
- 将概率性分析包装为自然人身份、违法属性或法律责任的确定结论

## 3. 角色与职责

- **文件责任人（质量负责人）**：维护本文件的准确性、可执行性和变更记录。
- **批准人（项目负责人）**：确认范围、风险、资源和对外承诺边界。
- **质量负责人**：验证本文件是否与质量手册、记录控制和审计要求一致。
- **执行人员**：仅在授权范围内操作，发现前提不成立时立即停止并升级。
- **独立复核人员**：不得直接复制执行人员的结论，应重新核对证据链和关键计算。

## 4. 核心原则

1. 原始证据不可覆盖；修订、派生和展示对象必须保持独立身份。
2. 链上技术事实、规则推断、统计推断、主体归属意见和法律判断分层表达。
3. 第三方RPC、区块浏览器和商业标签库只能作为辅助来源，不能成为关键事实的唯一依据。
4. AI或Agent只能执行受控检索、候选生成和一致性检查，不得独立批准最终结论。
5. 任何结果都必须能够指向输入、工具版本、参数、环境、执行人、复核人和适用方法。
6. 证据不足、来源冲突或方法越界时，系统应输出事实缺口、候选集合或无法判断。

## 5. 详细控制要求

### GOV-002-C001｜文件层级定义

- **控制目的**：在文档层级与单一权威来源中，使“文件层级定义”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：“文件层级定义”应被拆分为可验证步骤；每一步都要指定责任角色、前置条件、执行记录、异常分支和完成定义。
- **输入条件**：“文件层级定义”的输入至少包含原始对象或正式记录、采集时间、数据源等级、当前版本以及前序环节的通过证据。
- **执行记录**：“文件层级定义”不得只保存最终截图；应同时保存机器可读结果、过滤条件、排序规则、失败尝试和人工复核批注。
- **验收证据**：以受控记录与哈希清单证明“文件层级定义”已经执行；仅有会议纪要、口头确认或界面截图不构成充分证据。
- **阻断条件**：出现“来源、授权或对象身份无法确认”，或“文件层级定义”的关键输入无法回溯时，停止强结论并创建异常记录。
- **责任角色**：质量负责人负责“文件层级定义”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

### GOV-002-C002｜单一权威来源

- **控制目的**：在文档层级与单一权威来源中，使“单一权威来源”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：对“单一权威来源”的判断不得仅依赖界面展示或供应商结论，关键事实应能够回溯至原始对象、协议字段或受控记录。
- **输入条件**：进入“单一权威来源”环节前，应确认案件状态允许、所需数据完整、依赖工具已批准且不存在未关闭的P1不符合。
- **执行记录**：完成“单一权威来源”时，执行人应登记正常路径和异常路径，特别说明数据源切换、重试、舍入、排除和降级行为。
- **验收证据**：设计评审记录；证据必须直接显示“单一权威来源”的输入、实际输出、复核差异和最终处置。
- **阻断条件**：如果关键字段在独立来源间冲突且无法解释，则“单一权威来源”只能输出事实缺口或候选集合，不得自动降级数据源后继续。
- **责任角色**：质量负责人负责“单一权威来源”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

### GOV-002-C003｜文件编号规则

- **控制目的**：在文档层级与单一权威来源中，使“文件编号规则”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：实施“文件编号规则”时应优先保证可重现性和证据完整性，而不是追求最大覆盖率；无法满足前提时输出拒绝结论。
- **输入条件**：对于“文件编号规则”，执行人需先列出要验证的事实、允许使用的数据源和不能回答的问题，复核人确认后开始。
- **执行记录**：执行记录应逐步说明如何处理“文件编号规则”，保存实际命令、API参数、原始响应或表单字段，并记录每次人工选择的理由。
- **验收证据**：至少提交一份与“文件编号规则”对应的方法确认报告，并附正常、边界和失败样本的对象ID及哈希。
- **阻断条件**：当“文件编号规则”超出已验证方法范围、复核无法重现或工具版本、参数或运行环境未锁定时，必须阻断发布。
- **责任角色**：技术负责人负责“文件编号规则”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

### GOV-002-C004｜主文档与附件关系

- **控制目的**：在文档层级与单一权威来源中，使“主文档与附件关系”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：“主文档与附件关系”发生变更后，应重新执行影响分析、回归验证和人员授权确认，历史案件是否受影响必须形成书面结论。
- **输入条件**：处理“主文档与附件关系”前，必须取得与该主题直接相关的对象ID、来源ID、授权记录、适用方法版本和执行人员授权。
- **执行记录**：系统需为“主文档与附件关系”生成唯一运行ID，将输入对象、输出对象、工具制品哈希、参数快照、开始结束时间和异常事件绑定。
- **验收证据**：验收包包含“主文档与附件关系”的工具验证报告、独立重算结果、异常记录和适用范围声明。
- **阻断条件**：发现方法超出已验证范围后，隔离“主文档与附件关系”相关结果，评估对当前和历史案件的影响，再决定返工或撤回。
- **责任角色**：方法负责人负责“主文档与附件关系”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

- **执行记录**：系统需为“文档冲突处理”生成唯一运行ID，将输入对象、输出对象、工具制品哈希、参数快照、开始结束时间和异常事件绑定。
- **验收证据**：验收包包含“文档冲突处理”的工具验证报告、独立重算结果、异常记录和适用范围声明。
- **阻断条件**：发现方法超出已验证范围后，隔离“文档冲突处理”相关结果，评估对当前和历史案件的影响，再决定返工或撤回。
- **责任角色**：项目负责人负责“文档冲突处理”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

### GOV-002-C013｜发布渠道

- **控制目的**：在文档层级与单一权威来源中，使“发布渠道”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：“发布渠道”应被拆分为可验证步骤；每一步都要指定责任角色、前置条件、执行记录、异常分支和完成定义。
- **输入条件**：“发布渠道”的输入至少包含原始对象或正式记录、采集时间、数据源等级、当前版本以及前序环节的通过证据。
- **执行记录**：“发布渠道”不得只保存最终截图；应同时保存机器可读结果、过滤条件、排序规则、失败尝试和人工复核批注。
- **验收证据**：以操作日志与录像索引证明“发布渠道”已经执行；仅有会议纪要、口头确认或界面截图不构成充分证据。
- **阻断条件**：出现“无法由第二人员按记录复现”，或“发布渠道”的关键输入无法回溯时，停止强结论并创建异常记录。
- **责任角色**：质量负责人负责“发布渠道”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

### GOV-002-C014｜历史版本检索

- **控制目的**：在文档层级与单一权威来源中，使“历史版本检索”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：对“历史版本检索”的判断不得仅依赖界面展示或供应商结论，关键事实应能够回溯至原始对象、协议字段或受控记录。
- **输入条件**：进入“历史版本检索”环节前，应确认案件状态允许、所需数据完整、依赖工具已批准且不存在未关闭的P1不符合。
- **执行记录**：完成“历史版本检索”时，执行人应登记正常路径和异常路径，特别说明数据源切换、重试、舍入、排除和降级行为。
- **验收证据**：独立复核记录；证据必须直接显示“历史版本检索”的输入、实际输出、复核差异和最终处置。
- **阻断条件**：如果证据完整性校验失败，则“历史版本检索”只能输出事实缺口或候选集合，不得自动降级数据源后继续。
- **责任角色**：质量负责人负责“历史版本检索”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。
