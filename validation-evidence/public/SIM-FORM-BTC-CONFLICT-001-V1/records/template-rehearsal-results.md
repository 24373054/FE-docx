# 六份模板第二次不同场景演练结果

## 1. 场景

来源为冻结的`VAL-METHOD-T1-PROBE-001`。本次不重新采集网络数据，而是再摄取父包，摘录P0冲突，并验证模板能否在不掩盖冲突的情况下触发停止、保留依赖和阻断发布。

## 2. 结果

|模板|第二次演练技术结果|新增发现|成熟度处理|
|---|---|---|---|
|FRM-002|passed|组织授权与技术范围可分离；公司具名授权仍缺|保持模板草案|
|FRM-003|passed|再摄取需记录父包ID、manifest哈希、根哈希和是否产生新网络数据|保持模板草案|
|FRM-004|partial_pass|现有Schema不能机器表达跨包父对象和依赖交付模式|保持模板草案|
|FRM-008|passed|需分开记录源运行阻断、预期停止控制通过和方法未确认|保持模板草案|
|FRM-009|partial_pass|客户端、运行时、数据源和在线服务后端不能混为一个工具|保持模板草案|
|FRM-010|passed|预期阻断与独立复核失败必须分开|保持模板草案|

## 3. 生命周期判定

六份模板均完成第二个不同场景的字段演练，但不升级为`受控草案`，原因：

1. 两次演练均由同一研究会话编制和自检；
2. 没有公司具名填写人、独立复核人和批准人；
3. FRM-004和FRM-009仍有结构缺口；
4. 对应Schema和控制目录尚未实施；
5. 模板没有形成不可变PDF、电子签名或受控表单实例。

## 4. 下一步

- 对六份模板形成0.3.0候选修订；
- 由公司指定的不同自然人执行第三次角色分离演练；
- 同步修订证据manifest Schema的跨包依赖结构；
- 对在线数据源建立独立于工具制品的登记与批准模型；
- 具名复核通过前，所有模板保持`模板草案（待实测）`。
