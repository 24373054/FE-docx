# Bitcoin创世区块端到端记录链模拟报告

报告ID：`RPT-SIM-BTC-GENESIS-001-V1`

报告类型：内部研究/模拟报告

状态：`technical_reproduction_passed_governance_blocked`

## 1. 模拟事项

验证既有公开Bitcoin创世区块对象能否在不依赖原Python计算结果文件的情况下，由PowerShell/.NET实现从原始hex重算：

- 解码字节数；
- 交易数；
- 区块哈希；
- 交易ID；
- 单交易区块的Merkle根一致性。

不回答地址身份、资金性质、法律责任、方法生产适用性、工具生产适用性或司法鉴定问题。

## 2. 数据来源

- 来源证据包：`GT-BTC-GENESIS-001-V1`；
- 本包原始对象：`OBJ-SIM-BTC-RAW-001`；
- 文件：`raw/block.hex`；
- 文件SHA-256：`6f91a7dde963795146048aef2e347d02214edf6e0f841fc72950759c891e32bb`；
- 来源包状态：`truth_prepared`，未获真值批准。

## 3. 方法与工具

- 方法：MTH-BTC-UTXO 0.2.0中的T1确定性子集；
- 实现：PowerShell 7.6.4与.NET SHA-256；
- 输入：去除文件末尾换行后的hex解码字节；
- 区块哈希：80字节头两次SHA-256并反转显示；
- 交易ID：字节区间`[81,285)`两次SHA-256并反转显示；
- Merkle检查：本对象仅一笔交易，因此头内Merkle根显示值应等于交易ID。

方法和工具均未获生产授权。

## 5. 异常

本模拟包第一次人工录入hex时出现复制错误，文件SHA-256和字节数与来源不一致。该错误在manifest生成前由完整性检查发现，错误内容被替换，修复后对象与来源文件SHA-256一致。该异常表明：

- 原始对象必须由哈希和字节数接收；
- 人工复制不能作为证据取得方式；
- 异常记录需要关联错误对象、发现控制和修复对象。
