# 报告编制、批准、交付与更正SOP

## 1. 文件目的

本程序规定区块链电子数据研究/技术分析报告从任务核对、内容分层、证据引用、复核、批准、封装、交付、回执到更正或撤回的全过程。

当前项目没有司法鉴定机构及司法鉴定人授权证据，报告不得命名为司法鉴定意见书、使用司法鉴定专用章或暗示具有相应资质。对外报告类型、合同文字和宣传口径须经合规批准；当前仅允许模拟或内部研究报告演练。

## 2. 适用范围与禁止事项

### 2.1 纳入

- 内部研究报告、方法验证报告、技术事实整理和经批准的技术分析报告；
- 表格、图、附件、证据对象索引和可复算材料；
- 报告技术复核、质量复核、合规审查和具名批准；
- 加密交付、接收回执、更正、补充和撤回。

### 2.2 禁止

- 超出委托、授权、方法验证或人员授权范围；
- 将地址、聚类、标签、规则或模型输出写成自然人身份、违法属性或法律责任的确定结论；
- 把区块链存证规则泛化为公共链追踪授权；
- 把哈希一致写成来源真实、方法有效或保管链完整；
- 无批准、无复核或P0差异未关闭即交付；
- 事后覆盖已交付报告或删除错误版本；
- 把扫描签字图片、姓名文本和数字签名混为一体。

## 3. 角色与发布权限

|角色|职责|不得单独完成|
|---|---|---|
|报告编制人|按冻结结果和模板起草并建立引用|批准自己的最终报告|
|技术复核人|复算P0事实、计算和引用|只做文字校对|
|质量复核人|核对流程、缺陷、版本、记录和发布门|豁免未关闭P0差异|
|合规审查人|核对主体资格、服务边界、措辞、披露和接收方|把技术结论改成法律结论|
|报告批准人|接受范围、限制和残余风险|批准超授权或无证据包报告|
|交付执行人|按批准对象/渠道封装并取得回执|自行扩大接收方或附件|
|证据管理员|保留版本、容器哈希、交付和更正事件|覆盖历史版本|

缺少任何适用角色时报告保持`draft`或`blocked`。

## 4. 报告状态机

```text
draft -> technical_review -> quality_compliance_review -> approved -> packaged -> delivered
  \             \                     \                    \           \
 blocked       disputed              rejected             blocked     corrected/withdrawn
```

|状态|允许动作|
|---|---|
|`draft`|编制与内部修改|
|`technical_review`|冻结内容后技术复核|
|`quality_compliance_review`|质量、合规和披露检查|
|`approved`|内容和附件不再修改|
|`packaged`|形成交付包和容器哈希|
|`delivered`|有接收回执|
|`corrected`|已由新版本更正|
|`withdrawn`|已撤回且通知范围完成|
|`blocked`/`disputed`|不得交付|

内容、附件或接收方在`approved`后改变，必须回到相应复核门并生成新版本。

## 5. 详细控制要求

|控制ID|控制主题|强制要求|停止/拒绝条件|
|---|---|---|---|
|SOP-004-C001|报告编号|唯一报告ID关联案件/项目、分析运行、证据包和版本；不得复用撤回编号|编号冲突或无法关联冻结结果|
|SOP-004-C002|模板版本|使用批准模板ID/版本并记录偏离；技术服务报告与司法鉴定文书样式区分|无模板版本或擅用受限文书|
|SOP-004-C003|委托事项|逐字/等义记录已批准事项、回答边界和不回答事项|范围含糊、越权或要求法律定性|
|SOP-004-C004|检材来源|列明对象、来源、提供/采集主体、时间、包ID、完整性值及限制|只写“链上数据”或来源断链|
|SOP-004-C005|方法版本|每项结果引用方法ID、版本、状态、适用范围和偏离|方法未授权、暂停或超范围|
|SOP-004-C006|工具版本|记录支持关键结果的工具、版本/构建、验证状态和用途|以供应商界面作唯一依据|
|SOP-004-C007|技术事实|事实引用对象/字段/偏移和解析方法，避免身份或法律含义外推|关键事实无法复算|
|SOP-004-C008|规则推断|规则ID、版本、输入、命中条件、反例和禁止表述同结论展示|规则输出被写成协议事实|
|SOP-004-C009|统计推断|模型/统计方法、验证范围、性能、阈值、样本和不确定性可见|无验证性能或超范围概率解释|
|SOP-004-C010|限制|逐项写明链、网络、时期、来源、字段、方法、规则和外部证据限制|只用通用免责声明|
|SOP-004-C011|无法判断|前提不足、数据缺失、冲突或方法不适用时明确原因及已完成工作|为避免空结论而猜测|
|SOP-004-C012|图表|图表引用冻结数据，标明单位、方向、时间、过滤、聚合、标签来源和截断|图表夸大或无法对应数据|
|SOP-004-C013|金额校验|金额按资产最小单位复算，披露费用、未知项、估值来源和舍入|跨资产直接相加或浮点误差|
|SOP-004-C014|地址校验|地址/交易ID按链网络格式和原始对象核对；地址不等于主体身份|网络混淆、截断或标签冒充校验|
|SOP-004-C015|附件索引|列出附件ID、版本、对象数、哈希、分类、页/文件数和正文引用|正文引用不存在或附件版本不一致|
|SOP-004-C016|复核意见|保留技术、质量、合规意见、处理、关闭证据和未采纳理由|删除分歧或口头关闭|
|SOP-004-C017|批准签名|批准记录含身份、权限、版本、时间和决定；数字签名另按密码学规则验签|签名范围不明、代签或未验签却称数字签名|
|SOP-004-C018|加密交付|敏感包使用批准加密和独立密钥通道，记录明/密文哈希及解密验证|密码同通道或无法恢复|
|SOP-004-C019|接收回执|接收方独立核对报告/包ID、容器哈希、对象数、时间和异常|只证明发送、无回执或哈希不符|
|SOP-004-C020|更正|错误影响分析、修订原因、前后版本、复核、批准和通知均记录|覆盖原报告或静默换附件|
|SOP-004-C021|撤回|重大错误、越权、证据完整性或资格表述问题触发撤回并冻结使用|发现重大影响仍仅更正措辞|
|SOP-004-C022|通知范围|按实际接收者、下游依赖、传播可能和风险登记通知、确认和未达对象|只通知最初委托人却忽略已知下游|

22项控制当前均为`not_implemented`。

## 6. 报告启动与模板选择

报告负责人在起草前核对：

- 任务、授权、接收方和使用目的；
- 报告主体有权提供的服务类型与禁止称谓；
- 分析运行状态已`approved_for_reporting`；
- 证据包、方法、工具、人员和复核范围；
- 数据分类、最小披露和交付渠道；
- 模板版本、语言、附件和可访问性要求；
- 无法判断或范围缩小是否需要先与委托方确认。

### 6.1 报告类型

|类型|允许内容|必须声明|
|---|---|---|
|内部研究报告|假设、未验证方法、候选结果|不得用于案件或对外依赖|
|方法/工具验证报告|计划、样本、结果、差异和限制|验证状态及未覆盖范围|
|技术事实整理|可复算链上/电子数据事实|不含主体身份与法律定性|
|受限技术分析|获批的计算和推断|规则层级、限制、使用范围|

任何“司法鉴定意见书”类型在取得相应主体、人员、范围和程序证据前均不可选择。

## 7. 报告最低结构

1. 标识、版本、分类和状态；
2. 委托/研究事项与不回答事项；
3. 授权、检材/数据来源和接收范围；
4. 方法、工具、环境和偏离；
5. 已执行步骤及证据包引用；
6. 技术事实；
7. 确定性计算；
8. 规则/统计推断（如有）；
9. 反向证据、替代解释和分歧；
10. 结论及等级；
11. 具体限制和无法判断项；
12. 复核、批准和签名状态；
13. 附件索引与验证说明；
14. 更正/撤回历史（如有）。

不得在执行摘要省略会改变结论含义的限制。

## 8. 内容编制规则

### 8.1 事实与推断

推荐表达：

- “原始对象`OBJ-X`的字段`Y`按方法`M/V`解析为`Z`。”
- “在冻结数据集`D`和参数`P`内，确定性计算结果为`Z`。”
- “规则`R/V`命中对象集合`S`，该命中不能单独证明主体归属。”
- “由于来源冲突/方法未覆盖，无法判断`Q`。”

禁止表达：

- “地址必然属于某人”；
- “资金必然为违法所得”；
- “已穿透全部混币/跨链路径”；
- “哈希一致所以采集前内容绝对真实”；
- “区块链记录因此不可质疑”。

### 8.2 金额和估值

- 原生数量与法币估值分开；
- 最小单位整数、显示单位和小数位均写明；
- 费用、铸造、销毁、未知项单独列示；
- 估值注明价格源、市场、时点、报价币种、换算和限制；
- 不提供资产处置或交易定价建议，除非另有获批业务制度。

### 8.3 地址和身份

- 展示完整地址或受控缩写规则，并提供可核对附件；
- 明确链和网络，避免同格式跨网络混淆；
- 校验和格式检查只证明字符串符合规则；
- 标签写明供应商/来源、获取日期和置信限制；
- 主体关联引用合法外部证据，不由链上地址单独得出。

### 8.4 图表

- 数据和生成参数进入附件；
- 图例、单位、方向、时间、聚合和截断可见；
- 视觉颜色不用于暗示犯罪或责任；
- 隐藏小额边、孤立节点或未命中结果必须说明；
- 图中每条关键边可以回到交易/事件对象。

## 9. 复核与批准

### 9.1 技术复核

技术复核人：

1. 核对报告与冻结分析快照一致；
2. 复算全部P0事实、金额、路径和关键规则；
3. 抽查对象引用、图表数据和附件哈希；
4. 检查事实/推断层级与结论等级；
5. 检查替代解释、反向证据和无法判断；
6. 登记差异、影响和关闭证据。

### 9.2 质量与合规复核

- 文件编号、版本、模板、状态和追踪记录；
- 授权、主体资格、报告名称、用章/签名边界；
- 方法、工具、人员状态与适用范围；
- 数据最小化、个人信息、商业秘密和接收方；
- 复核独立性、P0差异、偏离和CAPA；
- 交付格式、加密、回执和留存计划。

### 9.3 批准

批准人只能对已冻结的报告版本和附件集合做：

- `approved_for_delivery`；
- `approved_with_restrictions`（限制进入报告正文）；
- `rejected`；
- `returned_for_revision`。

批准签字记录与密码学数字签名分开。当前未验证数字签名能力，不得标记报告为密码学已签名。

## 10. 封装、交付与回执

### 10.1 封装

- 从批准版本生成交付包；
- 清单列出报告、附件、验证材料、对象数和哈希；
- 生成包根哈希和容器哈希；
- 敏感包按批准算法加密；
- 交付副本与内部完整包建立来源关系；
- 组装后任何修改须重新复核和批准。

### 10.2 交付

交付执行人核对接收方身份、权限、渠道、到期和最小披露。发送事件记录：

- 报告/包ID与版本；
- 接收方及授权依据；
- 渠道、时间和容器哈希；
- 密钥交付通道；
- 实际发送状态和异常。

### 10.3 回执

接收方回执应包含：

- 实际接收时间；
- 报告/包ID和版本；
- 容器哈希和对象/附件数量；
- 解密、打开和完整性结果；
- 接受、拒绝或带异常接受；
- 接收主体。

系统“发送成功”“链接已创建”“已读”均不能替代完整性回执。

## 11. 更正、补充与撤回

### 11.1 错误分级

|等级|例子|默认动作|
|---|---|---|
|E0|不影响含义的排版|下一版修复并记录|
|E1|非关键附件索引/措辞|更正并通知接收方|
|E2|P1事实、图表或限制|影响分析、复核后更正|
|E3|P0金额、路径、对象、方法或结论|停止依赖并紧急更正/撤回|
|E4|授权越界、资格误导、证据篡改或重大泄露|立即撤回并升级管理/合规|

### 11.2 更正流程

1. 冻结原报告并记录发现时间/来源。
2. 确定受影响事实、结论、附件、案件和接收方。
3. 决定更正、补充或撤回。
4. 生成新版本，不覆盖原文件。
5. 重新技术、质量、合规复核和批准。
6. 按通知清单发送并取得回执。
7. 记录未能通知对象和残余风险。

### 11.3 撤回

撤回通知至少说明报告ID/版本、停止依赖要求、原因类别、影响、替代版本（如有）、联系人和确认方式。撤回不删除历史报告；存储状态改为`withdrawn`并限制访问。

## 12. 执行检查点与停止条件

### CP-1 启动

- [ ] 报告类型、主体资格、委托事项和接收方已核对；
- [ ] 分析运行获准进入报告；
- [ ] 模板与报告名称合规；
- **停止**：要求司法鉴定称谓、越权事项或未知接收用途。

### CP-2 内容

- [ ] 事实、计算、规则、统计和人工判断分层；
- [ ] P0事实有对象级引用；
- [ ] 负向证据、替代解释、无法判断和具体限制可见；
- **停止**：身份/违法确定性外推、证据断链或限制被弱化。

### CP-3 复核

- [ ] 技术复核重算P0；
- [ ] 质量、合规和披露检查完成；
- [ ] 分歧和未采纳意见有记录；
- **停止**：复核不独立、P0差异、方法/工具/人员状态不符。

### CP-4 批准与签名

- [ ] 批准身份、权限、版本和附件范围明确；
- [ ] 手写/电子审批与数字签名类型区分；
- [ ] 数字签名只有验签通过才标记有效；
- **停止**：代签、签名范围歧义或批准后内容变化。

### CP-5 交付

- [ ] 最小披露、加密、容器哈希和密钥通道符合批准；
- [ ] 接收方独立校验并回执；
- [ ] 无回执时状态保持未交付；
- **停止**：接收方不明、密码同通道、哈希不符。

### CP-6 更正/撤回

- [ ] 错误分级和影响范围已确定；
- [ ] 历史版本未覆盖；
- [ ] 实际和下游接收方纳入通知；
- **停止**：重大错误继续使用或只静默换文件。

## 13. 最低记录集

- 报告启动、类型选择和资格/授权核对；
- 报告ID、模板、版本和冻结分析运行；
- 证据、方法、工具、人员和附件索引；
- 技术、质量、合规复核及差异关闭；
- 批准身份、权限、决定、时间和签名类型；
- 交付清单、明/密文哈希、渠道和密钥分发；
- 接收回执；
- 错误、影响分析、更正/撤回、通知和确认。
