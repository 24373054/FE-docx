# 变更、基线与发布程序

## 1. 文件目的

控制文档、方法、模板、Schema、验证脚本、配置、节点和未来系统制品的变更与发布，确保影响、评审、测试、批准、监控和回滚有证据。

本项目不包含产品代码开发。现有代码仅限文档质量、证据包验证和研究复算脚本；“代码审查、灰度、数据库迁移”只有在对应对象实际存在且纳入范围时才适用。

## 2. 当前状态与范围

- 当前只有本地Git分支，未授权push、PR或生产发布；
- 文档提交不等于公司批准，研究基线不等于方法/工具/生产发布；
- 没有生产数据库、部署平台或客户系统；
- 所有发布应标明对象类型、成熟度与禁止声明；
- 紧急变更不能绕过事后评审和历史影响。

## 3. 变更类型与状态

|类型|例子|最低门|
|---|---|---|
|文档/目录|QMS、SOP、CSV|语义复核、索引、链接|
|方法/真值|规则、样本、P0字段|QMS-003/005再确认|
|工具/脚本|验证器、复算脚本|QMS-004、回归|
|Schema/数据|manifest、字段、迁移|兼容与恢复|
|节点/配置|客户端、RPC、参数|SOP-006|
|生产（未来）|服务/系统制品|全部阶段门|

状态：`draft → reviewed → approved_for_release → released → monitored → closed/rolled_back`。

## 4. 角色与分离

提出、实现、技术审查、质量审查、批准、发布和发布后复核应按风险分离。发布人不能修改已批准制品；作者不能以合并权限代替批准。

## 5. 详细控制要求

### SOP-007-C001｜变更单

- 每项变更应有唯一ID、原因、对象、前后状态、影响、风险、测试、回滚和责任人。
- 未登记变更不得进入受控基线。

### SOP-007-C002｜发布分支

- 应明确来源分支、目标基线、提交范围和工作树状态。
- 分支名称不产生环境或成熟度含义。

### SOP-007-C003｜代码审查

- 对实际存在的脚本/软件变更，应由未主要实现者核对逻辑、错误、安全和复现。
- 无产品代码时不得用该控制宣称产品工程完成。

### SOP-007-C004｜依赖锁定

- 应记录运行时、库、容器、外部API、Schema和数据源版本/哈希。
- 无法锁定的依赖应说明漂移风险和验证策略。

### SOP-007-C005｜制品签名

- 制品应有哈希或经验证签名，绑定对象、版本、构建者和时间。
- 哈希/签名不证明内容获批，仍需批准证据。

### SOP-007-C006｜数据库迁移

- 只有存在受控数据库时才适用；须定义前后Schema、备份、转换、验证和回退。
- 当前应记录不适用，不虚构迁移通过。

### SOP-007-C007｜配置差异

- 发布包应列出环境、节点、权限、参数和秘密引用的配置差异。
- 未解释差异不得默认继承。

### SOP-007-C008｜方法同步

- 工具/脚本/配置变化影响方法时应同步方法版本、范围、验证和授权。
- 不得发布与批准方法不一致的实现。

### SOP-007-C009｜文档同步

- 相关程序、操作、限制、来源、索引和发布记录应在同一基线一致。
- 先发布实现后补文档须作为偏离批准。

### SOP-007-C010｜模板同步

- 字段、Schema、示例、导出和报告引用应兼容。
- 模板结构改变应评估历史记录读取和迁移。

### SOP-007-C011｜权限变更

- 新功能/环境所需账户、角色、数据和秘密权限应最小化并到期。
- 回滚或人员变化时验证权限撤销。

### SOP-007-C012｜回归测试

- 回归覆盖正常、边界、冲突、恶意、历史样本和已知缺陷。
- 只运行新增正常路径不能批准发布。

### SOP-007-C013｜安全测试

- 按变更风险执行秘密、依赖、权限、输入、日志、数据和恢复检查。
- 高危发现未关闭时阻断发布。

### SOP-007-C014｜发布批准

- 批准人应核对对象、范围、测试、差异、残余风险、窗口和回滚。
- Git提交、合并、标签或自动检查不等于发布批准。

### SOP-007-C015｜维护窗口

- 应通知影响、开始/结束、冻结、值守、回滚点和禁止活动。
- 当前无生产服务时不得虚构维护窗口执行。

### SOP-007-C016｜灰度

- 未来灰度应定义隔离人群/任务、指标、时长、退出和数据边界。
- 真实案件不得成为未经批准的实验流量。

### SOP-007-C017｜监控

- 发布后监控功能、P0差异、性能、安全、日志、数据和用户影响。
- 没有生产总体时只报告验证运行，不报告线上稳定性。

### SOP-007-C018｜回滚

- 回滚触发、目标、数据兼容、权限、人员和验证须在发布前冻结。
- 无法安全回滚的变更需更高批准或拆分。

### SOP-007-C019｜发布后复核

- 不同人员应核对实际制品、配置、状态、指标、异常和回滚就绪。
- 发布者自检不能单独关闭高风险发布。

### SOP-007-C020｜关闭

- 关闭需完成监控周期、差异/CAPA、文档索引、权限、回滚决定和经验记录。
- 未关闭项、限制和历史影响必须保留。

## 6. 标准工作流程

1. 创建变更单和影响清单；
2. 冻结对象、依赖和配置；
3. 实施并完成技术/质量/安全审查；
4. 回归、恢复和回滚验证；
5. 同步方法、文档、模板和权限；
6. 具名批准对象类型和范围；
7. 发布并保存实际制品/提交；
8. 发布后独立复核和监控；
9. 回滚或关闭并更新基线。

## 7. 发布性质

每次记录必须选择：文档发布、数据/Schema发布、方法发布、工具发布或生产发布。较低层发布不得暗示较高层已完成。

## 8. 主要风险与控制

|风险|控制|停止|
|---|---|---|
|提交即批准|状态与签批分离|批准缺失|
|依赖漂移|锁定与制品哈希|不可复现|
|文档/方法不同步|影响清单|范围冲突|
|回归不足|多场景样本|P0未覆盖|
|无法回滚|发布前演练|恢复不明|
|真实任务做灰度|数据边界|未授权流量|

## 9. 记录

变更单、审查、制品/哈希、依赖、测试、批准、窗口、监控、差异、回滚和关闭按QMS-002保存。

## 10. 验收准则

- [ ] 对象类型和成熟度明确；
- [ ] 变更、依赖、配置与影响完整；
- [ ] 技术、质量、安全和批准必要分离；
- [ ] 回归、恢复和回滚实际验证；
- [ ] 方法、文档、模板和权限同步；
- [ ] 当前未宣称远端或生产发布。

## 11. 当前结论

程序已重构；当前只允许本地研究文档基线，不授权远端、工具、方法或生产发布。

## 12. 执行检查点与停止条件

- [ ] 变更单和影响批准；
- [ ] 制品、依赖、配置冻结；
- [ ] 测试和回滚证据通过；
- [ ] 文件/方法/模板/权限同步；
- [ ] 具名发布批准和监控责任人到位。

未审查变更、P0失败、高危安全问题、状态不一致、权限越权或回滚不可用时立即停止。
