# 证据存储、访问、移交与销毁SOP

## 1. 文件目的

规范证据入库、分层存储、访问、复制、导出、移交、回执、长期验证、迁移、法律保留和销毁。

本文件是生产体系中的单一权威来源。与旧版本、会议纪要、原型界面或口头约定不一致时，除非存在经批准的变更单，否则以本文件及其引用的受控记录为准。

## 2. 适用范围

### 2.1 纳入范围

- 证据存储、访问、移交与销毁SOP涉及的研发、验证、运行和质量活动
- 对外技术服务前的内部评审与批准
- 相关人员、工具、数据、场所和供应商的受控管理

### 2.2 明确排除

- 替代司法行政、市场监管、法院、检察机关或公安机关的法定判断
- 未经授权的数据获取、身份调查、交易撮合或资产处置
- 将概率性分析包装为自然人身份、违法属性或法律责任的确定结论

## 3. 角色与职责

- **文件责任人（证据管理员）**：维护本文件的准确性、可执行性和变更记录。
- **批准人（质量负责人）**：确认范围、风险、资源和对外承诺边界。
- **质量负责人**：验证本文件是否与质量手册、记录控制和审计要求一致。
- **执行人员**：仅在授权范围内操作，发现前提不成立时立即停止并升级。
- **独立复核人员**：不得直接复制执行人员的结论，应重新核对证据链和关键计算。

## 4. 核心原则

1. 原始证据不可覆盖；修订、派生和展示对象必须保持独立身份。
2. 链上技术事实、规则推断、统计推断、主体归属意见和法律判断分层表达。
3. 第三方RPC、区块浏览器和商业标签库只能作为辅助来源，不能成为关键事实的唯一依据。
4. AI或Agent只能执行受控检索、候选生成和一致性检查，不得独立批准最终结论。
5. 任何结果都必须能够指向输入、工具版本、参数、环境、执行人、复核人和适用方法。
6. 证据不足、来源冲突或方法越界时，系统应输出事实缺口、候选集合或无法判断。

## 5. 详细控制要求

### SOP-005-C001｜入库清单

- **控制目的**：在证据存储、访问、移交与销毁SOP中，使“入库清单”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：“入库清单”应被拆分为可验证步骤；每一步都要指定责任角色、前置条件、执行记录、异常分支和完成定义。
- **输入条件**：“入库清单”的输入至少包含原始对象或正式记录、采集时间、数据源等级、当前版本以及前序环节的通过证据。
- **执行记录**：“入库清单”不得只保存最终截图；应同时保存机器可读结果、过滤条件、排序规则、失败尝试和人工复核批注。
- **验收证据**：以受控记录与哈希清单证明“入库清单”已经执行；仅有会议纪要、口头确认或界面截图不构成充分证据。
- **阻断条件**：出现“来源、授权或对象身份无法确认”，或“入库清单”的关键输入无法回溯时，停止强结论并创建异常记录。
- **责任角色**：证据管理员负责“入库清单”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

### SOP-005-C002｜存储等级

- **控制目的**：在证据存储、访问、移交与销毁SOP中，使“存储等级”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：对“存储等级”的判断不得仅依赖界面展示或供应商结论，关键事实应能够回溯至原始对象、协议字段或受控记录。
- **输入条件**：进入“存储等级”环节前，应确认案件状态允许、所需数据完整、依赖工具已批准且不存在未关闭的P1不符合。
- **执行记录**：完成“存储等级”时，执行人应登记正常路径和异常路径，特别说明数据源切换、重试、舍入、排除和降级行为。
- **验收证据**：设计评审记录；证据必须直接显示“存储等级”的输入、实际输出、复核差异和最终处置。
- **阻断条件**：如果关键字段在独立来源间冲突且无法解释，则“存储等级”只能输出事实缺口或候选集合，不得自动降级数据源后继续。
- **责任角色**：质量负责人负责“存储等级”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

### SOP-005-C003｜WORM

- **控制目的**：在证据存储、访问、移交与销毁SOP中，使“WORM”形成可验证、可追溯、可复核并可在失败时安全停止的生产能力。
- **强制要求**：实施“WORM”时应优先保证可重现性和证据完整性，而不是追求最大覆盖率；无法满足前提时输出拒绝结论。
- **输入条件**：对于“WORM”，执行人需先列出要验证的事实、允许使用的数据源和不能回答的问题，复核人确认后开始。
- **执行记录**：执行记录应逐步说明如何处理“WORM”，保存实际命令、API参数、原始响应或表单字段，并记录每次人工选择的理由。
- **验收证据**：至少提交一份与“WORM”对应的方法确认报告，并附正常、边界和失败样本的对象ID及哈希。
- **阻断条件**：当“WORM”超出已验证方法范围、复核无法重现或工具版本、参数或运行环境未锁定时，必须阻断发布。
- **责任角色**：技术负责人负责“WORM”的执行或管理；质量负责人核对关闭证据，批准人处理超出既定风险容忍度的事项。

## 10. 验收准则

- [ ] 证据存储、访问、移交与销毁SOP中的每项强制要求均映射到需求、控制和至少一个测试用例。
- [ ] 执行人员可仅依据本文件和受控表单完成证据存储、访问、移交与销毁SOP相关流程，不依赖未记录的口头知识。
- [ ] 至少一名独立人员能够复现关键结果并解释差异。
- [ ] 失败路径、拒绝结论和异常升级机制经过演练。
- [ ] 关联脚本、模板、接口和目录链接均通过自动检查。
- [ ] 不存在未完成占位、失效路径或未经批准的对外承诺。

### 值班与升级

- P1事件：可能影响证据完整性、多个案件或敏感数据，立即通知安全、质量和管理层并停止相关发布。
- P2事件：影响单一案件但有可控替代路径，两小时内指定负责人并形成临时控制。
- P3事件：不影响结论的操作问题，纳入当日记录并在案件关闭前解决。
