# 任务受理与范围评审程序

## 1. 文件目的

在接收任何材料、数据、费用或对外承诺前，核验委托主体、联系人权限、授权依据、技术问题、数据来源、服务边界、能力、冲突、安全和交付条件。

本程序统一称“任务”。只有在取得相应司法鉴定主体与人员登记、并批准法定受案流程后，才能使用“案件受理”“鉴定委托”等可能产生法定含义的称谓。

## 2. 当前状态与适用边界

- 项目处于G0，尚无批准服务目录、合同模板、受理人员或真实任务；
- GOV-010未签批前，不得以公司名义联系客户、接收材料或报价；
- 司法鉴定、一般技术服务、合作研发、监管咨询和内部验证应分开登记；
- 不受理私钥保管、资产托管、兑换、撮合、定价、代收代付或资产处置；
- 不承诺解冻、追回、立案、采信、定罪或办案期限。

## 3. 受理类型与状态

|类型|允许主体|报告/输出|当前状态|
|---|---|---|---|
|内部公开研究|公司内部批准项目|研究记录|可在G0边界内|
|受控技术服务|经批准公司主体|技术事实/限制报告|未批准|
|合作机构任务|合同明确的持证/合格机构|按责任与签章边界|未批准|
|司法鉴定委托|登记主体和鉴定人|法定文书|禁止|

状态：

```text
inquiry → screening → review_pending → accepted/rejected
                                   ↘ conditional/clarification
accepted → active → changed/suspended → closed
```

## 4. 角色与独立性

|角色|责任|不得做|
|---|---|---|
|受理员|登记、核验、收集信息|承诺结论或法律结果|
|合规负责人|主体、服务、数据和负面清单|替代主管机关/律师结论|
|技术/方法负责人|可行性、方法、工具和能力|接受超验证范围任务|
|质量负责人|状态、冲突、记录和停止门|以格式通过替代能力|
|安全/数据负责人|数据来源、传输、存储和删除|允许未授权敏感数据|
|预算/合同负责人|费用、付款、采购和责任|成功收费影响结论|
|批准人|接受、条件、拒绝和范围变更|批准超出主体权限|

## 5. 详细控制要求

### SOP-001-C001｜委托方身份

- 受理前应核验自然人/组织名称、主体证明、统一社会信用代码或等效身份及实际关系。
- 无法核验或身份与任务利益不一致时不得接收数据。

### SOP-001-C002｜联系人权限

- 应核验联系人代表委托方提出需求、传输数据、接受报告和决定变更的书面权限。
- 邮箱、名片、聊天账号或职位名称不能单独证明授权。

### SOP-001-C003｜委托材料

- 应建立拟接收材料清单，记录类型、数量、格式、来源、密级和预期移交方式。
- 未完成预评审前只接收最小必要的非敏感说明，不接收原始检材。

### SOP-001-C004｜授权依据

- 每项数据获取、持有、分析、共享和交付都应有可核验授权或法律依据。
- “链上公开”不能自动授权链下身份、账户、设备或个人信息处理。

### SOP-001-C005｜技术问题

- 技术问题应拆为可回答的对象、链/网络、时间、输入、输出和判定边界。
- “查清资金”“认定诈骗”“确定控制人”等混合问题必须拆分或拒绝。

### SOP-001-C006｜法律问题排除

- 应把罪名、责任、权属、主观故意、证据采信和强制措施等法律判断列为排除或外部法律输入。
- 技术报告不得以措辞暗示内部已作法律裁判。

### SOP-001-C007｜检材清单

- 未来检材清单应有唯一ID、描述、载体、数量、封装、完整性和交接状态。
- 当前无批准检材接收能力时，清单只能作为候选字段。

### SOP-001-C008｜数据来源

- 应登记原始持有人、获取方式、时间、系统、权限、完整性和派生链。
- 第三方RPC、浏览器和标签库不得作为关键事实唯一来源。

### SOP-001-C009｜时间范围

- 应明确起止、时区、区块高度/时间、确认/最终性规则和历史数据可用性。
- 模糊时间或动态状态无法冻结时应限定结论或要求补充。

### SOP-001-C010｜链与资产范围

- 应列明链、网络、主网/测试网、协议、资产/合约、桥和地址格式。
- 一条链的授权和方法不得自动扩展到其他链或链下平台。

### SOP-001-C011｜已知假设

- 所有身份、地址控制、标签、时间、汇率和交易语义假设应在接受前登记来源和可证伪条件。
- 未经验证的假设不得写入事实层输出。

### SOP-001-C012｜交付物

- 应约定报告、证据包、机器可读数据、图表、说明会和不交付项目。
- 交付物不得超出主体、方法、工具、人员或数据许可。

### SOP-001-C013｜时限

- 时限应从数据、方法、复核、外部依赖和异常缓冲估算。
- 不承诺法院、监管、银行、平台或第三方处理期限。

### SOP-001-C014｜费用

- 费用应说明计费范围、税费、外部成本、变更和退款/中止规则。
- 不采用与结论方向、追回金额、解冻或案件成功绑定的技术结论收费。

### SOP-001-C015｜利益冲突

- 任务分派前应按ORG-005核验客户、对方、对象、供应商、资产和人员关系。
- 无法控制的冲突应拒绝、回避或转介，不得只披露后继续。

### SOP-001-C016｜数据安全

- 应确定密级、传输、存储、访问、地域、保留、删除和事件责任。
- 安全条件未满足时不得要求委托方“先发数据再补手续”。

### SOP-001-C017｜转委托限制

- 外包、分包、合作机构和云服务使用应取得明确授权并满足QMS-012。
- 未批准的转委托不得通过通用合同条款默示同意。

### SOP-001-C018｜受理决定

- 受理、条件受理、补充、拒绝或转介应由具名有权人员记录事实与证据。
- 条件未完成前不得开通生产权限或正式执行。

### SOP-001-C019｜拒绝理由

- 拒绝理由应具体到主体、授权、范围、能力、冲突、安全、资源或禁止活动。
- 拒绝不得包含未经证据支持的违法评价，并按必要范围保密。

### SOP-001-C020｜范围变更

- 任何对象、链、时间、数据、方法、结论、交付、期限或费用变化应重新评审和批准。
- 口头追加、即时聊天或执行中发现的新线索不能自动扩大授权。

## 6. 标准工作流程

1. 仅登记最小询问信息；
2. 核验委托方、联系人和主体权限；
3. 拆解技术问题与法律排除；
4. 形成材料、来源、时间、链和假设清单；
5. 合规、技术、质量、安全、冲突和资源并行评审；
6. 冻结交付、时限、费用、分包与数据条款；
7. 有权批准人作出受理、条件、补充、拒绝或转介；
8. 受理后才创建任务ID、权限和采集计划；
9. 范围变化重新执行评审；
10. 关闭时核对交付、返还/保留、费用和未结事项。

## 7. 决策矩阵

|条件|决定|
|---|---|
|主体/联系人不可核验|拒绝或补充|
|数据授权/来源不明|拒绝接收数据|
|问题属于法律判断|拆分、外部法律输入或拒绝|
|方法/工具/人员未批准|保持研究/验证，不受理|
|存在不可控冲突|回避、转介或拒绝|
|安全/存储未就绪|暂停|
|可行但需补充|条件受理，不执行|

## 8. 主要风险与控制

|风险|控制|停止条件|
|---|---|---|
|销售先承诺|签约前多角色评审|未经批准报价/结论|
|敏感数据先到|最小信息门|授权/存储未就绪|
|技术与法律混同|问题拆解|强法律结论|
|公开链等于无限授权|来源与目的限制|链下数据无依据|
|成功收费|费用审查|结果激励|
|口头扩范围|变更控制|无新批准|
|合作方借名|主体/签章界面|责任不清|

## 9. 记录与保密

使用[FRM-001](../09-templates/01-case-intake-form.md)和[FRM-002](../09-templates/02-authorization-scope-form.md)或等效系统。询问、拒绝和未受理材料同样按密级、最小保留和访问控制管理。

## 10. 验收准则

- [ ] 公司主体和允许服务目录已批准；
- [ ] 受理、合规、技术、质量、安全和批准角色具名；
- [ ] 合同、授权、数据和负面清单经法律评审；
- [ ] 受理前不会接收真实检材或敏感数据；
- [ ] 技术问题与法律判断明确分层；
- [ ] 范围、方法、人员、工具和交付一致；
- [ ] 利益冲突与分包规则实际演练；
- [ ] 条件、拒绝和范围变更均能阻断执行；
- [ ] 当前真实受理数量保持0。

## 11. 当前结论

程序已从通用生成稿重构为受控草案。当前没有公司受理权限、服务目录、人员或真实任务，故SOP-002至005只能用于公开/模拟验证。

## 12. 执行检查点与停止条件

### 12.1 执行前检查

- [ ] E-01至E-03已批准；
- [ ] 委托方与联系人权限可核验；
- [ ] 授权覆盖全部数据和目的；
- [ ] 技术问题、法律排除和交付已冻结；
- [ ] 方法、工具、人员、场所和安全均有效；
- [ ] 冲突、分包、费用和期限已评审；
- [ ] 条件项全部关闭。

### 12.2 立即停止

主体或授权不明、收到未授权敏感数据、任务触及禁止金融活动、方法/人员越权、利益冲突不可控、数据完整性或安全失败、范围被口头扩大时，立即停止并转QMS-009或SOP-008。
